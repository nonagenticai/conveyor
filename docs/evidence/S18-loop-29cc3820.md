## Blocker found and recorded: the `baseline` arm cannot complete at this revision

The S17 one-shot `arm="baseline"` run was attempted first:
`01a20a04-fc66-7c36-a4d6-6ce6c86317ff` (12 instances, model `local-llm`). The producer **is** built
and produced patches (`benchmark.case.produce` → `ok`, one context-cap `no_attempt`,
inference-524 retries), but the run driver still hard-refuses every produced baseline patch:

```text
apps/server/src/benchmark_worker.rs:240-244
"baseline" => return Err(JobFailure::permanent(
    "the baseline producer (the baseline.py port) is not built yet"))
```

The run was cancelled and the reaper failed it (`status=failed`, 0 graded). This is stale S17 code
that #12's P2 producer did not update; it is a code fix plus a new deploy, deliberately **not** made
inside #30 (whose scope is the proof and its receipt). The loop's baseline therefore had to be a
succeeded `conveyor` run promoted explicitly — exactly the S18 plan §9.2 semantics for a
capability baseline. A live `baseline`-arm comparison is a follow-up issue.
