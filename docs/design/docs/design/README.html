Web UI design

The latest design is studio.html — the SPEC_V2 organisational operating model. Open it directly in a browser; no build or server is required. When data/snapshot.js is present (written by conveyor snapshot), the pages it covers render the conveyor's own rows — Portfolio, Organisation, Jobs, Metering and the Plan Boards tab — and carry a LIVE ribbon with the snapshot hash and timestamp; an unwired destination or tab keeps the V2 · PROPOSED ribbon. The Plan Boards tab is a join, not a seed: it renders each project's GitHub issues from the issue registry fetched at publish, joined to the conveyor's own cards and runs. A unit with no real card is shown as not intaken. V1 surfaces implemented in the Rust app are unlabelled.

Two surfaces, one pack. Published at https://nonagentic.ai/design/ the pack is the read-only public snapshot: no accounts, no backend call, the privacy contract unchanged. Served by the app itself at https://conveyor.nonagentic.ai/design/ the same pack is the operator console: console.js finds the same-origin /config.json, signs in against the realm the server already trusts (auth-code + PKCE S256, token in memory), and the Plan Boards tab reads and writes the platform's own rows — intake an issue as a card, move it, comment, claim and release. Signed out, or on the homepage, nothing changes: no API request and no write control.

The Projects destination is the programme workspace: the seeded projects, a project's board, plan link and linked issues, its text outputs (compose, edit, publish flag) and the public feedback inbox. Signed in it can edit a project (projects.update, If-Match), intake a feedback issue, compose an output and Publish — which enqueues a job that builds the pack and opens a pull request on the homepage repository; it never merges. On the homepage the same page is read-only from the snapshot.

Without a snapshot, every service result is an offline fixture. With data/snapshot.js, the platform's public rows replace those fixtures on the pages that have a live source; docs/design/scripts/check-data.cjs verifies the manifest hashes, the secret-metadata-only rule and the email/token redaction. See STUDIO-SPEC.md for sources, boundaries and verification.

The pack is published at https://nonagentic.ai/design/ by the nonagentic_homepage repository, which copies this directory verbatim into dist/design/ and serves studio.html as index.html. Opening studio.html directly is still the offline entry point. The app image also serves the pack at /design: the web stage copies the generated documents (docs/) and the data directory (the placeholder snapshot and the public issue registry) beside the runtime files, so the console's Documents destination and data links resolve. node docs/design/scripts/check-console.cjs is the console gate: a signed-out pack makes zero API requests, a signed-in one sends the actions it renders, and the 401/412 paths are rendered.

Documents

scripts/build-docs.py renders every docs/**/*.md and the root README.md to docs/<repo path>.html (for example docs/SPEC_V2.html, docs/plans/00-INDEX.html) and writes the index to docs/documents.json + docs/documents.js. The pages are standalone — local fonts, local stylesheet, no fetch — so they work from file:// and from the published site.

  • Links between documents resolve to their generated .html page; links to any other tracked file resolve to the GitHub main URL, so a reader never lands on a 404.
  • Regenerate with python3 docs/design/scripts/build-docs.py (requires pandoc) and commit the output. node docs/design/scripts/check-docs.cjs is the gate; it needs no pandoc.
  • The Documents destination in studio.html reads docs/documents.js. Without that file (a clean checkout before generation) the destination says so instead of rendering a broken list.

Platform outputs are the second document source: a publishable text output is rendered at publish time to docs/output-<id>.html and indexed by docs/outputs.js (window.CONVEYOR_OUTPUTS = {schema:"design-outputs/v1", …}); the Documents destination adds a Platform outputs group. A clean checkout carries the null placeholder and shows no group; a body is rendered with raw HTML neutralised, so the public page has no executable markup from an author.

Feedback

The public surface is GitHub, not a service. studio.html links the repository's Discussions and opens a prefilled issue with the feedback label from every page; the snapshot's manifest.feedback_url carries the target, and data/feedback.json publishes the feedback issues that exist. The issue template is .github/ISSUE_TEMPLATE/feedback.yml.

The console lists the feedback-labelled issues on the Projects destination and can intake one into a project's intake lane (cards.create carrying meta.issue); the issue stays the GitHub unit and is not modified.
