Phases

The phase set is preliminary and a through h: the full ADM, tailored for software delivery — Preliminary once per organisation, A–H per architecture initiative. An architecture project carries a row per phase; the phase gate is architecture.phases_advance, which closes a phase on its mandatory set and its contract, refuses naming the missing artefact or the contract's state, and writes no approval row.

No phase is skippable in this profile: each closes on its mandatory set, and where the adopted row names a contract kind (A, F, G, H) on that contract too. B–E carry no contract kind in the capability yet, so their closures are their mandatory sets.

The plateau rule is the design's: the PSA is the project-start set; the HLD adds the business, data, application and technology views; the SD adds process, interface, migration and platform detail. A delivery project's brief names the plateau its own architecture inception satisfies — PSA for every project, HLD for one that changes the blueprint, SD for one that changes the estate.

The Preliminary set is real, not named: its three artefacts are approved at version 2 with their entries and links. The Phase A set is recorded but not yet populated — the only Phase A row today is the SAW, which is a contract, not an artefact.

What the profile does not yet have. The standard ships ten types and none of the 26 architecture.* actions adds one: artifact_type is written only by seed_standard_tx in crates/store/src/architecture.rs, and the profile tailoring action changes which seeded types a phase requires, not what types exist. A new type is a store change and a release.

Phases E–H carry no mandatory types yet. Their phase rows exist in the set, but no seeded type names E, F, G or H and the adopted row names no contract kind for E. An advance of Phase E therefore passes an empty requirement set with nothing to satisfy, and F–H close only where the row's kind applies. A phase that can be passed without a refusal is the profile's largest gap.

The P0 table is the target, not the current state. The design names for these phases business service/function and value-stream catalogues; business interaction and actor/role matrices; footprint and functional-decomposition diagrams; data-entity/business-function and application/data matrices; conceptual and logical data diagrams; application portfolio and interface catalogues; technology portfolios; the application/technology matrix; platform-decomposition and environments diagrams; gap analysis, candidate solutions and work packages; project context and benefits diagrams; roadmap, increments, dependencies and cost/benefit; the compliance review; and the change record. None of those types is seeded. The adopted row is a correct but partial encoding — ten types against that table — and it grows by seeding, not by tailoring. The profile row and the artefact standard are aggregates of their own rather than artefacts in the repository, so the Preliminary mandatory set names only the three artefact types that record the baseline.

The Phase A SAW is live: 01a1f2c2-0e1a-787f-9011-46b424d1ec71, version 2, approved 2026-11-19T07:50:28.603416Z. Its six acceptance criteria: D1, an approved artefact is immutable, a supersede writes version 2, and reuse is searchable across plateaus; D2, the profile names each phase's mandatory set by plateau and the baselines carry their nine and seven dimensions; D3, an approved artefact set and a live contract advance a phase, a draft artefact refuses the advance naming it, and a contract change re-opens the gate; D4, a design gate without a live contract refuses, a superseded contract refuses naming its status, and a review takes one compliance level and a waiver a dated owner; D5, a review's exactly-one outcome is a change row or a kata candidate; D6, the Architecture destination renders its tabs from the live aggregates. Its scope is the eleven tables of migrations/0054_architecture.sql and the 26 architecture.* actions in crates/actions/src/architecture.rs.

Contract discipline: a contract change is a new version and re-opens its gate, and an approved body is immutable. A delivery design gate resolves only against a live approved contract trace-linked to the delivery project — absent, draft and superseded all refuse and write no approval row. Only the Phase A SAW exists as a contract row today; the other three kinds are defined by the profile and instantiate when an initiative reaches F, G or H.
