Tailored ADM profile — T9 TOGAF ADM capability (retrospective, 2026-11-22)

Phases

The profile runs Preliminary and phases A–H. An architecture project materialises each phase as a wbs_node(kind='phase'), and a phase cannot be skipped (SPEC_V2 §8.1, plan §4.3). Preliminary establishes the capability before any architecture work: the principles, the profile itself, the artefact standard and repository, the Board, governance and contracts, and the maturity and skills baseline. Phases A–F each close on an approved contract; G is the per-delivery compliance review; H is the change review that produces exactly one change or kata.

Artefacts by phase and plateau

The seeded artifact_type standard names each type's phase, plateau and mandatory flag. The profile filters it: a young capability carries fewer artefacts, and the set grows with the assessed maturity. The plateaus are psa (Project Start Architecture), hld (High-Level Design) and sd (Solution Design); the profile decides which plateau a phase requires. This rework publishes seven Phase A–D artefacts: a stakeholder matrix, two Phase-A catalogs, a Phase-A solution concept diagram, a Phase-B business capability map, a Phase-C data entity catalog and a Phase-D technology standards catalog. crates/api/tests/architecture_capability.rs::the_profile_names_the_mandatory_set proves the filtered mandatory set is returned per phase and plateau.

Contracts

Four contract kinds close the ADM work: statement_of_architecture_work at Phase A (assignment, scope, responsibilities, acceptance criteria), delivery_contract after F (delivery commitments and the compliance method), statement_of_intent at completion (intended use, ownership, measures of effectiveness) and request_for_architecture_work at Phase H (further work). A contract change is a new version and re-opens its gate; the approved body is immutable (§8.1). togaf_architecture_phases.rs::a_contract_change_reopens_the_gate proves the re-open.

Adoption

The Board adopts the profile through an approved decision; the adoption path is the one v1-p81-1 and v1-p81-3 hardened, and v1-w2a-3 remains open because any UUID is accepted as the board decision. A draft profile cannot govern: togaf_profile_gates.rs::an_absent_or_partial_profile_set_does_not_satisfy_the_gate and ::a_draft_profile_cannot_govern_the_gate prove the refusal.
