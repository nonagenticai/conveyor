Build vs reuse

Build: the five meeting tables; the twelve actions; the console screen; the participant extension; the minutes kind; the card type and seed; the instruments and flag.

Reuse, never rebuild: the approval lifecycle, the card/run path, the governed-asset lifecycle, the dependency edge, the board and cadence rows. The meeting is a composition over these primitives; a second decision table, a separate meeting-decision table, or a chat store is rejected by §6.8's first principle.

The one core-table decision: a job-binding seat must write an approval_decision row. The existing approver_id FK is human-only, so T19 adds nullable approver_id, job_binding_id, participant_kind, an exactly-one CHECK, and a partial unique index. The alternative — writing L1 decision rows for job seats — would split the decision record and is rejected.

Constraints and licences

All work is in this repository; the tables, actions, console and tests use the existing Rust workspace and Leptos app. No third-party licence is introduced. No calendar or AV service is integrated; an ICS feed is a read of attendance. The MCP surface is the existing stateless infrastructure contract; no new port or external runtime is used.
