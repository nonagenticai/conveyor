Build vs reuse

Build the spine in the conveyor. The plan-spine rows are tenant-scoped facts that every later slice reads; a separate service would create a second source of truth for the same projects and would have to reimplement the approval and tenancy primitives. The build is five new tables/migrations and two action families, exercised through the existing action layer.

The alternatives considered and rejected:

  1. Port a WBS from the V1 outline tree. Rejected as the primary model. outline_node is a requirements outline with no typed WSJF inputs, no baseline, and no acceptance-by-artefact. A new wbs_node with a project-scoped tree and the four typed integers is smaller than a migration of V1 rows, and it leaves outline untouched (open question 1's default).
  2. Keep meta.depends_on as the only dependency model. Rejected. It is a JSON list on one project, cannot name an edge kind or a status, and cannot refuse a cycle at creation. The new project_dependency edge table becomes the source; the gate can read it after the transition, with the JSON list retained as the seed's declared order until the seed is migrated.
  3. Store the WSJF score. Rejected. The spec is explicit: the four inputs are stored, the score is computed on read. Storing it would make a stale score look like a fact.
  4. Build the T10 cadence and benefits-realization procedures here. Rejected. T1 owns the rows and the gates; the cadence materialisation, PI planning and the realization procedure are T10. The benefit profile's six field groups are T1 because the row is the measurement record.

What this analysis changes for the build

The build order follows the dependencies inside the spine: the baseline and register first (P1), then the WSJF inputs on the WBS row (P2), then the portfolio read (P3), then the edge table and its cycle refusal (P4), then the MSP rows and their refusals (P5). The approval requester exclusion is the one cross-cutting change: it must land in the approval action before P1's change-request gate is meaningful. The T1 build remains blocked by #46 (ADR 0005's absorption sequence) and by P0; this analysis and the architecture beside it are the project's inception artefacts, not a claim on its build units.
