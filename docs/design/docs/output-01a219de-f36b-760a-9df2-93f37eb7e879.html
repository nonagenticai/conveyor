Twelve requirements carry the slice. R-01 to R-06 fix policy, convening, agenda, attendance, positions and the decision arithmetic; R-07 and R-08 dispose of outcomes and minutes; R-09 and R-10 carry the human seat and the metering; R-11 is the console destination; R-12 states the refusals that keep the design honest. Each functional requirement names the suite that verifies it in the plan, from meetings_policy through meetings_console, and the console adds the Playwright spec meetings.spec.ts.

The catalog is the requirement baseline for the slice, not a design. It states what must be true and leaves the schema, the SQL and the HTTP shapes to the solution concept and the data entity catalog. The non-functional row is a set of refusals: any implementation that adds a chat table, a transcript store, a calendar write path, a second decision store or an LLM that invents a position fails R-12 regardless of its other behaviour.
