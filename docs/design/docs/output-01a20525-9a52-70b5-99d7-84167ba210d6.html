Benefits Diagram — T13 Tool platform

The diagram is derived from the T13 inception analysis and architecture design: every goal below is a capability the tool spine adds, and every measure is a check the project's scenario table already executes.

Goals and outcomes

  • One governed call path. A job reaches a backend only through tools.call; the eight V1 external actions move onto toolkit operations. Outcome: no handler calls a service directly.
  • An effect ceiling that is data. tool.effect is the maximum and tool_binding.effect_ceiling narrows it; a destructive call without the tenant's approvals is refused before dispatch. Outcome: a job cannot widen its own authority.
  • A closed input schema. Undeclared properties, patterns and bounds are refused with zero network calls. Outcome: a backend receives only input the operator approved.
  • Sealed credentials and tenant-prefixed storage. A binding names a credential alias; the compiled prompt carries no key or URL. Outcome: the audit trail cannot leak the secret.
  • One ledger row per call. tool_call records the run, step, tool version, input hash, sizes, latency and error class. Outcome: the tool estate is countable and retirable.

Measures

  • Direct handler calls from a job: 0 (the externals_declared guard and the zero-hit grep).
  • Ledger rows per call: 1 (the one_call_is_one_ledger_row scenario).
  • A ceiling raise at run time: 403 tool_effect_forbidden.
  • An undeclared property or bound: 422 tool_input_invalid with zero requests.
  • An object round-trip: tenant-prefixed key, server-side encryption, content hash; the compiled prompt contains no S3 key.
  • A toolkit with no calls in a cycle: retired or justified (the B2 census).

Benefits and sub-benefits

  • B2 — Less bespoke tooling (primary). The benefit profile's target is: every service a job uses is a toolkit; a toolkit with no calls in a cycle is retired or justified. T13's contribution is the mechanism — the binding, the ledger and the ceiling that make the census possible.
    • Sub-benefit: the eight V1 external actions stop being bespoke dispatch paths.
    • Sub-benefit: a toolkit version is pinned; editing a service cannot silently change a run.
  • B1 — Auditable decisions (secondary). The tool_call ledger and the tool.called event give the decision ladder the call-level evidence it cites when a gate judges a tool effect.
  • The programme's benefit map links B2's output (the tool estate census) to its capability (governed calls), operational outcome (retirement or justification of unused tools) and strategic objective (less bespoke tooling); this document names the T13 outputs that feed that chain.
