Current state

At main@490ad555 the application measured 31 routes, 25 screen modules and 31 Playwright specs, all V1, and none of the ten SPEC_V2 §10.5 destinations existed. By the 2026-11-24 snapshot apps/web/src/app.rs registers /portfolio, /portfolio/:programme_id, /programme, /organisation, /procedures, /authoring, /plan, /improve, /operations, /execution, /design/adm and /tools, with /tools and /design/adm rendering ToolsGate and AdmGate; apps/web/e2e carries shell, portfolio, programme, organisation, procedures, authoring, plan, improve, operations, execution and admin specs. Reuse sources

Reuse apps/web/src/app.rs for the router, sidebar and top bar; api.rs for the action request shapes (If-Match, Idempotency-Key and the approval id); auth.rs for OIDC PKCE with an in-memory token; state.rs for the tenant, me and manifest signals; and sse.rs, components.rs and palette.rs for shared UI. Reuse the V1 screen modules and specs, the e2e harness (fixture.ts, dev-server.mjs and playwright.config.ts) and web.yml as the browser gate; the compiled action registry of SPEC_V2 §10.4; and the programme, work and measure read models owned by T1, T4 and T10. docs/design/v2.js and STUDIO-SPEC.md are the reviewed design reference (D64), never implementation evidence (D65).

Build vs reuse

Build only the route registry and shell, one screen module per destination and the execution room, one four-state Playwright spec per destination, and the coverage measurement in scripts/build-v2-coverage.py. Do not build a second frontend or router, SSR, a mobile app, new tables, actions, events or ports, or a rewrite of the design pack: the app stays one Leptos CSR/WASM application served by the same binary on port 8930. Where a destination's owning slice is absent, the screen renders not yet live and names the missing action or slice; a missing capability is a typed dependency (ADR 0013), not a local fetch or a fixture.

Risks

The obvious build fails in four ways. Measuring the design pack instead of apps/web credits mock pages, which is the D1 defect the coverage rule corrects and the check build-v2-coverage.py --check reveals. Rendering fixture data would make every screen look complete while hiding absent slices, and the no-fixture rule with the honest-gate specs exposes it. Parallelising the units would collide on the single-writer app.rs and screens/mod.rs, which sequencing issues #562 to #566 prevents. Treating the stale V2 coverage record or the red project-acceptance record as current would overstate delivery; regenerating both from the route table, the specs and acceptance/programme/T18.toml is the check.
