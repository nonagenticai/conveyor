Conformance and standards as row-derived sections

Status: design note for #783 — no code in this unit. Claim baseline main@e6f4c3ac9 (2026-11-27). The owner's decision (P4) is the merge gate and is not self-issued.

Why this note exists. Three Python generators still build the programme's own conformance record from a mixture of live rows, committed files and published pages, and then write files back. This note inventories every invariant they enforce, names one owner for each — a live action, a snapshot section, a committed standard, a one-off instrument, or the unit that closes a gap — and stages the replacement so no invariant is dropped on the way.

The one-owner rule in words. A write-time constraint belongs to the action that refuses it (A14-A16, A21-A22, A24, G1, G3-G5, G7). A completeness or consistency check over rows belongs to the engine's computed section, which reads the sections in §1 and never re-derives them (A1-A5, A7-A13, A17, A19-A20, A23, A25-A26, S1-S3, S5-S11, S13, G2). An external or frozen fact, a renderer or a build-integrity check stays a one-off (A6, A27-A30, A33, S8, S14). A gap names the unit that closes it (A18, A31-A32, S4, S12, G6). No invariant is assigned to a file scheduled for deletion.

Stage 0 is the load-bearing unit. It is the only stage that needs new engine code before any deletion; its section is the gate every later deletion leans on. It must reproduce the current audit's findings exactly (a golden test against the committed snapshot) before anything is removed. The conformance section reads the sections in §1; it does not re-derive them (P1.2).

Stages are independent after Stage 0. Stage 2 and Stage 3 touch disjoint files; Stage 4 is independent of both. Each is a separate issue, created only from this note once it is accepted.

5. P4 — the decision

Recommendation: accept. Adopt Stage 0 as the next unit (a conformance section and snapshot --strict in the engine), then Stage 1's deletions, then Stage 2/3/4 as separate units.

The decision options, for the record:

  1. Accept — the ownership map and the five stages as written; the next unit is Stage 0.
  2. Amend — e.g., keep the standards pages file-first and move only the conformance rules; or move Stage 4 (the ledger) ahead of Stage 2. Name the change; the note is revised before merge.
  3. Reject — the generators stay; the reason is recorded, and no unit is created from this note.

The two open questions the issue carries are answered in the recommendation:

  • The gap register: a register, not a new table. The register itself is a projection over rows — the conformance section computes it. The accepted-gap ledger (160 entries) is the record that needs rows: a registers.* register of accepted gaps with owner, expiry and disposition (Stage 4). No new table is proposed.
  • The standards record: a section plus published documents. The derivation (instances, status, findings) is the standards section; the pages are outputs rendered from it, with provenance (#756). Neither is a second derivation.

7. Risks and open points

  • The committed pack lags the live rows. The 199 gaps / 629 instances / 420 packages above are measured on docs/design/data at the claim baseline; the live publish (#526's lane) can differ. Stage 0's golden test must be taken on both the committed and the live snapshot.
  • The strict audit already fails on the committed pack (seed_live_drift T12 and a grown-ledger entry) because the committed pack is not the live publish snapshot. That is a known state, not a property of this note; the Stage 0 unit must reproduce the live verdict and treat the committed-pack delta as the stale-badge signal (#867), not as a new rule.
  • The standards page renderer stays. Rendering 629 HTML pages is a document renderer, not a record; it is out of scope for deletion and moves to the pack's own scripts.
  • The kata section is empty today. S12's owner (the kata.* actions) exists, but the snapshot has no kata section and the rows are zero. Stage 2 must not claim a kata derivation it cannot evidence; the note marks it a gap with the kata section unit.
