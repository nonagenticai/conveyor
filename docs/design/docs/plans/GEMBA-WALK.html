GEMBA-WALK — the Gemba Walk client

Owner direction: 2026-11-26 · ADR: docs/decisions/0021-gemba-walk-client.md (Accepted 2026-11-26 as a delegated rule decision) · Spec: docs/design/GEMBA-WALK-SPEC.md · Procedural set: docs/plans/inception/GEMBA-WALK/ · Baseline measured at main@d958824f8 and re-verified at main@0d6db794b (counts unchanged) and main@cedd84980 on 2026-11-26.

This plan is deliberately not a SPEC_V2 §12 T## slice. The programme-seed generator parses only docs/plans/slices/S*.md and **(T##)** rows in §12, so a T-row would silently change seed/programme.json and fail build-programme-seed.py --check. The walk is registered as a cross-cutting project in docs/plans/00-INDEX.md; the inception unit (#792) publishes the MSP/TOGAF/SAFe set and registers the project, and the build issues G0/S1–S4 are created after the publication gate.

1. Objective and gate

Build a second, game-style client of the conveyor at /walk/ with all features and all functionality — every read and every write through the existing registry — and measure it well enough that the owner can decide whether it becomes the primary UI.

Gate (P6): every §10.5 destination and every retained V1 route has a walk route and a Playwright spec asserting empty, error, happy and one refusal or write; every action in the frozen census is reachable and schema-rendered; the named write flows round-trip with the correct headers; the parity instrument is green with no expired exemption; accessibility and performance budgets are met; the owner signs the primacy decision. Until then apps/web is normative.

3. Scope

IN — a static client at /walk/; route parity with every apps/web path; the seven wings and the destination rooms; the full read and write contract; seats as view presets; the DOM sheet system; the schema-driven action sheet; the world port and the engine decision; the parity instrument and its evidence; per-destination Playwright specs; accessibility and performance budgets; deployment and the scoped deep-link fallback; the primacy runbook.

OUT — any new table, action, event, port or backend read model; a second decision store; a replacement for /design/; native mobile; chat/audio/video; customer care (D48); SSR; a public unauthenticated mode in v1; pixel parity with the mock; deleting apps/web before the gate.

"All functionality" is defined as: every §10.5 destination and every retained V1 route has a walk route and a spec; every manifest action is reachable and form-renderable; every destination's primary write flow is exercised end to end; every gate the server enforces is surfaced, never pre-empted. It is not defined as pixel or copy parity with either existing client.

4. Relationship to the programme

  • Not a §12 T## slice. The inception unit (#792) registers the project and publishes the inception set before any build issue is created; the registration is a reviewable data change through scripts/build-programme-seed.py and seed/programme-definition.json, never a hand-edit of seed/programme.json or docs/design/data/issues.json (see §8.1).
  • The V2 coverage instrument (D65, scripts/build-v2-coverage.py) continues to measure apps/web and is not touched. The walk's evidence is docs/evidence/walk-coverage.json.
  • The design pack (/design/) keeps its public role and is not rebuilt or embedded.

5. Architecture decisions (normative; detail in the spec)

  1. Static sub-site at /walk/, same image and origin, no new port.
  2. Route parity by construction: walk path = /walk + app path; /walk/ is the entrance.
  3. Full functionality through the existing contract; no backend surface.
  4. DOM sheets own all work; the world is navigation and state display only.
  5. Seats are view presets; the manifest and server scopes own authority.
  6. No fixtures; no client-side programme store; no published snapshot as the app's source.
  7. WorldView port; the simulation is bevy_ecs 0.20.1 in crates/walk-world (ADR 0022); the renderer is canvas-2D (ADR 0023, after the P0 spike measured it against WebGL2; WebGL2 remains a candidate behind the port).
  8. Clean URLs with a scoped /walk/* fallback in crates/api/src/web.rs (GET/HEAD, non-asset paths) and a Rust test; without it a deep link renders the operator app.
  9. Schema-driven action sheet so no action is unreachable; unsupported schema falls back to a labelled JSON editor.
  10. Parity is measured by a frozen census and per-destination specs, never by prose.

6. The parity model and instrument

scripts/build-walk-coverage.py (W0) is the only measure of walk parity. It must be able to run in CI with no server and no database.

Inputs

The frozen census docs/evidence/walk-census.json is written once at W0 and re-baselined only by a signed commit:

{
  "baseline": {"date": "YYYY-MM-DD", "git_sha": "<40 hex>"},
  "routes": [{"pattern": "/boards", "view": "BoardIndex", "spec": "v1/board.spec.ts"}],
  "actions": [{"name": "cards.move", "kind": "internal", "scopes": ["cards:write"],
               "effect": "write", "confirm": "none", "tenancy": "tenant",
               "idempotent": true}],
  "counts": {"routes": 52, "actions": 597}
}

The census is built from:

  • route patterns and views — scripts/build-v2-coverage.py:app_routes() and app_route_views() (its ROUTE regex, line 42), the same parser the V2 record uses;
  • action names, scopes, kind, effect, confirm, tenancy and idempotence — parsed from the #[action(...)] attributes under crates/actions/src/**/*.rs; the parsed names are cross-checked against the 597 names in docs/design/data/actions.json, so a parse miss fails the build instead of shrinking the census;
  • apps/walk/src/router/routes/{core,portfolio-organisation,procedures-governance,measure-operations-utilities,v1}.js — one row per surface (walk path, app path, room, spec file), composed by apps/walk/src/router/registry.js. One route file per delivery sibling; a sibling never edits another's file;
  • apps/walk/e2e/<wing>/*.spec.ts.

The census holds no live manifest and no server state.

Per-action states (each machine-checkable):

State Check
reachable the action name is in the census and the walk's action sheet can route to it
schema-rendered actions.describe's input schema produces a form or the documented JSON fallback
write-roundtrip a named destination flow invokes the action in dev and refetches its read model
approval-tested a destructive action without its approval is refused and the refusal is shown
sse-updated a subscribed screen reflects the topic (where the topic exists)

Per-destination states — absent, read, write, verified, with the spec path and the last green run. verified requires all four states plus the Playwright spec.

Behavioural parity — for each named flow, the same scripted task runs against apps/web and /walk/ in dev; the harness captures the POST /api/actions/{name}/invocations trace (names, status, order) and compares it. Pixels are not compared.

Exemptions — a separate signed record, docs/evidence/walk-exemptions.json, holding {surface, reason, signer, expires}; an expired exemption fails the gate. The owner or the plan's named maintainer signs; the default expiry is 30 days.

Output and check — docs/evidence/walk-coverage.json, emitted by python3 scripts/build-walk-coverage.py; --check exits non-zero when a census route has no registry row, a census action lacks reachable or schema-rendered, a destination lacks its spec, or an exemption is expired. The check runs in the walk workflow and in web.yml (or its successor) once the walk app is on main; it needs no server, database or network.

Dependencies. The parent blocks S1–S4. S1–S3 are parallel and file-disjoint. S4 is blocked-by S1–S3. The parent creates all five route files as empty row lists, so a sibling fills only its own file and the duplicate-PR guard (block-duplicate-pr.py) never sees overlapping edits.

Work-package map. W0–W2 are parts of the parent; W3–W4 are the destination work distributed across S1–S3 by wing; W5–W8 are S4. The stage table in §7 stays the content order; the split is by file ownership, not by read/write phase, because a destination module owns both its reads and its writes — splitting reads from writes would make the two issues touch the same files. Where a retained V1 route is already a §10.5 destination owned by S1–S3, S4 reuses that module and its route row, adding only the V1-retained spec trace; it never edits another sibling's file. Its src/destinations/v1/** holds only V1 surfaces with no owning destination module. W6 is an audit: a slice landing is a follow-on issue on the sibling that owns the destination, not an S4 edit, so the four wings stay file-disjoint.

Generated record. docs/evidence/walk-coverage.json is emitted by the instrument, never hand-edited; each issue that changes coverage regenerates and commits it. It is the only shared generated artifact in the split, and a generated-file overlap alone does not merge two siblings' work; every hand-edited file stays disjoint.

Shared seams. src/api/manifest.js, src/shell/sheet-host.js, src/world/port.js, src/forms/** and src/a11y/** are parent-owned; siblings consume them and do not edit them. A sibling that needs a seam change stops and asks the parent's owner rather than forking the contract.

If the split is withdrawn by change control, the whole plan is one issue (GEMBA-WALK), the stages are commits on one issue/<n>-gemba-walk branch, and the P6 gate closes the same PR. The plan states both paths so no session has to improvise.

11. Verification and definition of done

Per issue — the issue's own parts and acceptance criteria, its Playwright spec(s), the parity instrument's rows, and a contract test for each write (headers, refusal, refetch). An issue is not done because the screen renders; it is done when the state, the write and the refusal are proven.

Unit and type — node --test apps/walk/src and tsc --noEmit (JSDoc) pass; pure modules only.

Browser — npx playwright test -c apps/walk/playwright.config.ts with the dev server; every spec asserts empty, error, happy and one refusal or write; auth and deep-link gates included.

Parity — python3 scripts/build-walk-coverage.py --check exits 0; the record is committed; an expired exemption fails.

Accessibility — keyboard-only navigation of every wing; focus return; contrast from computed styles; 200% zoom and 390 px width with no horizontal scroll.

Performance — the §9 budgets; a 5-minute soak; the engine protocol recorded for ADR 0022.

Docs — python3 docs/design/scripts/build-docs.py and node docs/design/scripts/check-docs.cjs pass whenever a Markdown file changes.

DoD for the project — the P6 gate, not "the UI looks finished". Until P6 the plan's matrix is the truth and apps/web remains normative.

Rules

  • Claim the issue first (issue-pickup); no issue → no branch → no work. Work in .worktrees/issue-<n>, branch issue/<n>-<slug>, one PR with Closes #<n>. Slices are commits on that branch; they never get their own PR. lane/ branches and the global lane protocol do not apply in this repository.
  • The parent issue's five-sibling split is the only permitted split; a sibling that wants a sixth issue stops and asks the owner.
  • No Rust compilation on local hardware; the compile/lint verdict is the repository's GitHub-hosted preflight, and the PR's CI is the final gate. Record the run id on the issue.
  • No new table, action, event, port or decision store; if the walk seems to need one, stop and escalate — the answer is a contract-faithful screen, not a backend change.
  • The engine ADR (0022) precedes any Bevy code beyond the spike; until then the canvas baseline is the implementation.
  • Contract tests per issue: manifest gating, headers, refusal, refetch.
  • The Do-Not list in the spec is the review checklist for every PR.
