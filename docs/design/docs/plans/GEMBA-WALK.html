GEMBA-WALK — the Gemba Walk client

Owner direction: 2026-11-26 · ADR: docs/decisions/0021-gemba-walk-client.md · Spec: docs/design/GEMBA-WALK-SPEC.md · Baseline measured at main@d958824f8 on 2026-11-26.

This plan is deliberately not a SPEC_V2 §12 T## slice. The programme-seed generator parses only docs/plans/slices/S*.md and **(T##)** rows in §12, so a T-row would silently change seed/programme.json and fail build-programme-seed.py --check. The walk is registered as a cross-cutting project in docs/plans/00-INDEX.md; programme registration and the issue set are W0, taken only once the owner accepts ADR 0021.

1. Objective and gate

Build a second, game-style client of the conveyor at /walk/ with all features and all functionality — every read and every write through the existing registry — and measure it well enough that the owner can decide whether it becomes the primary UI.

Gate (P6): every §10.5 destination and every retained V1 route has a walk route and a Playwright spec asserting empty, error, happy and one refusal or write; every action in the frozen census is reachable and schema-rendered; the named write flows round-trip with the correct headers; the parity instrument is green with no expired exemption; accessibility and performance budgets are met; the owner signs the primacy decision. Until then apps/web is normative.

3. Scope

IN — a static client at /walk/; route parity with every apps/web path; the seven wings and the destination rooms; the full read and write contract; seats as view presets; the DOM sheet system; the schema-driven action sheet; the world port and the engine decision; the parity instrument and its evidence; per-destination Playwright specs; accessibility and performance budgets; deployment and the scoped deep-link fallback; the primacy runbook.

OUT — any new table, action, event, port or backend read model; a second decision store; a replacement for /design/; native mobile; chat/audio/video; customer care (D48); SSR; a public unauthenticated mode in v1; pixel parity with the mock; deleting apps/web before the gate.

"All functionality" is defined as: every §10.5 destination and every retained V1 route has a walk route and a spec; every manifest action is reachable and form-renderable; every destination's primary write flow is exercised end to end; every gate the server enforces is surfaced, never pre-empted. It is not defined as pixel or copy parity with either existing client.

4. Relationship to the programme

  • Not a §12 T## slice and not in seed/programme.json in this unit.
  • W0 registers a programme project and creates the unit issues once ADR 0021 is accepted; the registration is a separate, reviewable data change (seed/programme.json + the issue ledger).
  • The V2 coverage instrument (D65, scripts/build-v2-coverage.py) continues to measure apps/web and is not touched. The walk's evidence is docs/evidence/walk-coverage.json.
  • The design pack (/design/) keeps its public role and is not rebuilt or embedded.

5. Architecture decisions (normative; detail in the spec)

  1. Static sub-site at /walk/, same image and origin, no new port.
  2. Route parity by construction: walk path = /walk + app path; /walk/ is the entrance.
  3. Full functionality through the existing contract; no backend surface.
  4. DOM sheets own all work; the world is navigation and state display only.
  5. Seats are view presets; the manifest and server scopes own authority.
  6. No fixtures; no client-side programme store; no published snapshot as the app's source.
  7. WorldView port; canvas-2D baseline; Bevy 0.18 WASM candidate; ADR 0022 after the P0 spike.
  8. Clean URLs with a scoped /walk/* fallback in crates/api/src/web.rs (GET/HEAD, non-asset paths) and a Rust test; without it a deep link renders the operator app.
  9. Schema-driven action sheet so no action is unreachable; unsupported schema falls back to a labelled JSON editor.
  10. Parity is measured by a frozen census and per-destination specs, never by prose.

6. The parity model and instrument

scripts/build-walk-coverage.py (W0) is the only measure of walk parity. It must be able to run in CI with no server and no database.

Inputs

  • the frozen census docs/evidence/walk-census.json: baseline {date, git_sha}, the 52 app route patterns, the 597 action names and their scopes (names from docs/design/data/actions.json, the compiled registry dump; scopes from the action source scan used by build-v2-coverage.py);
  • apps/walk/src/router/registry.js: one row per surface (walk path, app path, room, spec file);
  • apps/walk/e2e/*.spec.ts.

Per-action states (each machine-checkable):

State Check
reachable the action name is in the census and the walk's action sheet can route to it
schema-rendered actions.describe's input schema produces a form or the documented JSON fallback
write-roundtrip a named destination flow invokes the action in dev and refetches its read model
approval-tested a destructive action without its approval is refused and the refusal is shown
sse-updated a subscribed screen reflects the topic (where the topic exists)

Per-destination states — absent, read, write, verified, with the spec path and the last green run. verified requires all four states plus the Playwright spec.

Behavioural parity — for each named flow, the same scripted task runs against apps/web and /walk/ in dev; the harness captures the POST /api/actions/{name}/invocations trace (names, status, order) and compares it. Pixels are not compared.

Exemptions — {surface, reason, signer, expires}; an expired exemption fails the gate. The owner or the plan's named maintainer signs; the default expiry is 30 days.

Output — docs/evidence/walk-coverage.json with a --check mode in the walk workflow and in web.yml (or its successor) once the walk app is on main.

11. Verification and definition of done

Per work package — the WP's own acceptance table, its Playwright spec(s), the parity instrument's rows, and a contract test for each write (headers, refusal, refetch). A WP is not done because the screen renders; it is done when the state, the write and the refusal are proven.

Unit and type — node --test apps/walk/src and tsc --noEmit (JSDoc) pass; pure modules only.

Browser — npx playwright test -c apps/walk/playwright.config.ts with the dev server; every spec asserts empty, error, happy and one refusal or write; auth and deep-link gates included.

Parity — python3 scripts/build-walk-coverage.py --check exits 0; the record is committed; an expired exemption fails.

Accessibility — keyboard-only navigation of every wing; focus return; contrast from computed styles; 200% zoom and 390 px width with no horizontal scroll.

Performance — the §9 budgets; a 5-minute soak; the engine protocol recorded for ADR 0022.

Docs — python3 docs/design/scripts/build-docs.py and node docs/design/scripts/check-docs.cjs pass whenever a Markdown file changes.

DoD for the project — the P6 gate, not "the UI looks finished". Until P6 the plan's matrix is the truth and apps/web remains normative.

Rules

  • One issue per WP; push the lane branch before the work; one PR per repo per unit; no second PR without the audited SECOND_PR= reason.
  • No Rust compilation on local hardware; the compile verdict is GitHub-hosted CI.
  • No new table, action, event, port or decision store; if the walk seems to need one, stop and escalate — the answer is a contract-faithful screen, not a backend change.
  • The engine ADR (0022) precedes any Bevy code beyond the spike; until then the canvas baseline is the implementation.
  • Contract tests per WP: manifest gating, headers, refusal, refetch.
  • The Do-Not list in the spec is the review checklist for every PR.

13. Non-goals

A second backend or decision store; SSR; a native mobile app; chat/AV; customer care; replacing the design pack; a public unauthenticated v1; pixel parity with the mock; retiring apps/web before the P6 gate; adding a SPEC_V2 §12 T## row or changing seed/programme.json in this unit.
