06 — Tool provenance and the retirement gate

Status: the method and per-source summary behind seed/tool_provenance.json · 2026-11-22 · unit #558. Authority above this file: docs/SPEC_V2.md §11.2 and §11.9, docs/decisions/0006-tool-absorption-grouping.md, docs/decisions/0007-tool-estate-conveyor-and-coding.md, and the inventory in docs/plans/04-TOOL-ESTATE-INVENTORY.md and docs/plans/05-W2V-ABSORPTION.md.

This file does not restate 04/05. It records how the capability diff was measured, where each source went, and what the repository now enforces. The machine-readable artifact is the seed; the gate is crates/actions/tests/tool_provenance.rs.

Method

  1. Inventory the sources the repository records, not the repositories themselves. The evidence is docs/plans/02-source-map/ (the retired work-management, board, gateway and flow surfaces), the analysis and evidence-review capture notes under docs/evidence/, and the in-repo OpenAPI locks for the four survivor services. No private repository, host, address or credential is named.
  2. One row per recorded capability. Where a source map records an operation family (/requirements*, /pm/projects, the board application's board/card surface), the row is the family. Where the contract is an OpenAPI lock, the row is the operation. A row is reviewable; a transcription of 548 work-management paths or 367 flow-engine operations is not.
  3. Disposition is one of three. ALREADY-PRESENT names the conveyor action or manifest tool that carries the capability. PORT names a live consumer and a usage sample, and either a manifest tool or the open unit that will provide it. DROP records the measurement date and the query or decision that justified dropping it.
  4. A retired source is never a destination. Only a live source carries service aliases. Every manifest service must be owned by a live source, and a retired, archived or migration source carries none — so adding a manifest cannot turn one into a destination. No retired product name is used as a source label.
  5. The gate runs with the suite. cargo nextest run -p conveyor-actions --test tool_provenance is part of scripts/ci/gate.sh; the seed is reviewed in the same PR as any manifest it targets.

What the seed proves today

  • Every one of the six manifest tools has an ALREADY-PRESENT row.
  • Every ALREADY-PRESENT target is a registered action or a published tool; the test resolves them against the live registry and manifests, not against a hand-maintained list.
  • Every manifest service is owned by a live source; no non-live source carries a service alias, so no retired application can become a destination.
  • Every DROP carries a date and a query or an owner decision.
  • Every PORT carries a live consumer and a usage sample; the eleven survivor rows name the open unit (#561 or #560) until their manifest tools exist.

Gaps this inventory exposes (not claimed here)

  • evidence_review was absorbed into apps/scientific; it has no manifest row yet. It needs a unit of its own once the scientific toolkit's read surface is settled.
  • strata_ingest is live and has no conveyor action or toolkit. It is a follow-on unit, not a row that can resolve today.
  • ops.* exists as an action family (18 actions, read verbs plus gated writes) but has no toolkit; host control is T7's mechanism decision, not a provenance row.
  • The four survivor services are pending rows, not omissions; #561 and #560 replace the pending with the published tool targets and keep this gate green.
