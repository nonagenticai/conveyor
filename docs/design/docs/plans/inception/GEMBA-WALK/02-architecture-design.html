GEMBA-WALK — Architecture design (PSA and HLD)

Context and boundary

GEMBA-WALK adds a second client, not a second system. It is a static sub-site at /walk/, served from the same image and origin as the API, with its own router, sheets, world and Playwright suite. It adds no table, action, event, port, decision store or read model. Every read is a literal GET route or a read action; every write is POST /api/actions/{name}/invocations with the standard envelope and headers; a capability the server does not expose is an honest gate.

The design covers the client architecture, the route/action parity model, the WorldView port, the seats-as-presets rule, the serving fallback and the parity instrument. apps/web remains the normative operator UI until the P6 gate. The design pack at /design/ is unchanged.

This is a tailored ADM set for a software delivery project; it is a document set now and imports as typed architecture_artifact rows when the T9 repository is used. Every artefact carries the standard's common metadata: title, status, version, owner, reviewer, review date, purpose, stakeholders, scope, related project and its published document; links use derivation | realization | reuse | dependency.

Aggregates, tables and actions

Project Start Architecture (Phase A–Preliminary)

A1 — Principles applied (catalog)

ID Principle Rationale Implication
P1 The contract is the product the walk exists to prove the action contract is UI-independent every read/write is the existing route/action; no client-only capability
P2 One backend, one decision store a second store or backend makes the record ambiguous no new table, action, event, port or read model
P3 The sheets own the work a canvas cannot carry tables, long text or audit-quality forms every record, form and decision is a DOM sheet with HTML semantics
P4 The world never gates a capability not every user will walk or use a pointer every room, record and action has a deep link and a keyboard path
P5 Seats are presets, not privileges authority lives in the manifest, scopes and server refusals changing a seat changes the landing and emphasis only
P6 No fixtures, no client store a fixture makes the measurement lie the client renders real rows or the honest gate; no snapshot as the app's source
P7 Parity is measured prose cannot prove a UI the frozen census and per-destination specs are the only credit
P8 Same identity, same origin a second identity path doubles the attack surface auth-code + PKCE, token in memory, tenant header, no localStorage token
P9 The engine is replaceable the engine choice is unproven WorldView is a port; canvas-2D is the baseline; Bevy is a candidate measured in P0
P10 The walk is reversible primacy must not be a one-way door additive surface, redirect map and an apps/web retirement as a later decision

D1 — Technology view

Static HTML/JS/CSS sub-site served from the existing image and origin; no new port. The baseline world is a canvas-2D projection behind WorldView; the candidate is Bevy 0.18 compiled to WASM, measured in P0 against bundle, startup, frame time, WebGL requirements, CI build and DOM-overlay input. Browser APIs: fetch, streams, Web Crypto (PKCE), sessionStorage (verifier only), history/URL. Build: GitHub-hosted preflight for the wasm compile (no local cargo); the walk's static assets are copied by the Dockerfile. Tests: Playwright against the dev server; node --test for pure modules. No SSR, no server runtime, no third-party hosted service.

Decisions

ID Decision Rationale Where it shows
AD1 A static sub-site at /walk/, same image and origin no new port, image or deploy path D1, serving fallback
AD2 Route parity by construction (/walk + app path) a missing route is visible, not invented router registry, census
AD3 Full functionality through the existing contract a second backend would fork the record C1/C2, R3/R4
AD4 DOM sheets own all work; the world is navigation/state display a canvas cannot carry audit-quality forms P3, A5
AD5 Seats are view presets; the manifest and scopes own authority a preset must never grant a permission B2, R9
AD6 No fixtures, no client programme store a fixture makes the parity claim false P6, R12
AD7 WorldView port; canvas baseline; Bevy measured in P0 the engine is unproven; the port keeps both R8, D1, ADR 0022
AD8 The instrument is a frozen census + per-destination specs live manifests move; the gate must stay passable plan §6, R13
AD9 Deep links served by a scoped /walk/* fallback + Rust test without it a deep link renders the operator app R7, W2

Acceptance

The delivery design gate: GEMBA-WALK operates under the P0 brief and the T9 capability. This set is the PSA/HLD evidence; a deviation (a second backend, a fixture, a canvas-only work surface, a seat that grants authority) is a change request, never a silent fork. The compliance review records one level against the delivery contract when the project closes. The full TOGAF repository rows are T9's; this set is publishable now and importable later.

The acceptance itself is the P6 gate in docs/plans/GEMBA-WALK.md §7 and §11, the instrument's record docs/evidence/walk-coverage.json, and the owner's primacy decision.
