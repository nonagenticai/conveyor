Build vs reuse

Build: the static sub-site (apps/walk/index.html, src/main.js, auth, api, forms, router registry, shell, world port, state, a11y); the DOM sheet system; the schema-driven action sheet; the seats presets; the canvas world and its WorldView implementation; the parity instrument and the frozen census; the Playwright suite; the serving fallback and Dockerfile copy; the walk CI workflow.

Reuse, never rebuild: the action registry, actions.describe, the invocation envelope and headers, the identity provider, the read models, the server's refusals and the design pack. The walk is a client of the existing contract; a capability the contract does not expose is an honest gate.

Reject: an iframe or WebView of the mock; a second backend; a second decision store; a localStorage programme state; any fixture or embedded snapshot; a new table, action, event or port.

The one architectural decision: the client is a static sub-site served from the same image and origin, with all work in DOM sheets and the world behind a WorldView port. That is what makes the engine replaceable (canvas-2D now, Bevy 0.18 candidate) without coupling a frame loop to the operator bundle.

Constraints and licences

  • Same image and origin, no new port; the Dockerfile copies the static output and web.rs serves it.
  • OIDC: the public client gains a /walk/ redirect URI (or a dedicated public client); this is an external identity-operator change, recorded as acceptance-blocked-by.
  • Engine candidates: canvas-2D (no dependency); Bevy 0.18 (Apache-2.0 OR MIT) only if the spike meets the budgets. Any embedded font must carry its licence; the mock's embedded font is not carried without its licence.
  • No private host, path, token or credential in any page; no-private-refs is a gate.
  • No new Rust dependency for the baseline; the Bevy candidate's build runs on GitHub preflight.
