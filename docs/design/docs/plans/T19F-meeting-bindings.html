T19F — Decision-forum governance (follow-on)

Programme project: T19F · plan issue #682 · implementation #683 · proof #684

Gate: a policy change is authored through the tenant's authoring route and published as a new immutable meeting_type version while an in-flight meeting keeps its pinned version; a board subject decision is taken in a board sitting, with one approval_decision row per qualifying seat carrying via='meeting'; a cadence row names its meeting type and materialises exactly one meeting; the direct architecture.board_decide path is unchanged; the T19F project is a live programme row with its MSP/TOGAF/SAFe artefact set and a closure review that defers closure to the tranche-6 review.

1. Objective

T19 made the meeting the decision forum, but left two seams open. A forum's policy could only be created implicitly by a schedule and never changed: the engine answers a policy change with "a policy change is a new version through the governance route", and that route did not exist. The T9 governance_body and T10 programme_cadence only resolved a meeting by convention — a body's key doubled as its standing type, and a cadence slot was passed by hand — so the board's decisions and the cadence's sittings were not bound to the forum records they belong to.

T19F closes both seams without rebuilding either consumer. It adds the versioned authoring route through T17, an explicit meeting-type binding on the body and the cadence row, a board-sitting entry that uses T19's own outcome arithmetic, and a cadence materialisation that is idempotent.

4. The model

4.1 Policy authoring is a versioned release, not an edit

meeting_type rows stay immutable. A change is a new authoring asset of kind='policy' whose payload carries the policy, reviewed by a human through authoring.review (an approved approval_id) and published by authoring.publish. Publication writes the next max(version)+1 row for the policy key in the same transaction and records the output link on the asset. The authoring asset key and the meeting-type key are different: a new version needs a new asset key carrying the same meeting_type_key, because T17 keeps one published row per (tenant, kind, key). A meeting pins meeting_type_id and meeting_type_version at schedule time; it never follows a later version.

4.2 The board sits through the meeting arithmetic

governance_body.meeting_type_key names the body's standing type explicitly (defaulting to the body key for existing rows). architecture.board_sit_open validates the body and the subject, opens the board approval and creates or reuses the live sitting with the body's type, then adds the approval as the deciding agenda item. Seats record positions; architecture.board_sit_decide calls T19's close_item_tx, so the quorum, the required departments, the meeting rule, the linked approval's stricter policy, P4 exclusion and the via='meeting' decision rows all come from the one arithmetic T19 already proves. A quorum miss defers inquorate; it is not an error. The direct architecture.board_decide writes its approval row as before; the sitting is the bound path.

4.3 A cadence row materialises its own meeting

programme_cadence.meeting_type_key names the forum type for PI planning, the demo, the retro or a refinement. cadences.materialise resolves the latest non-retired version, schedules the meeting with the slot, and returns the existing non-cancelled instance on a repeat. A partial unique index on (tenant_id, cadence_slot) for non-cancelled meetings makes "one cadence row, one meeting" the database's promise; a cancelled instance may be replaced.

4.4 What does not change

The direct board path, the approval primitive, T19's outcome arithmetic, the meeting DoD, the minutes gate, the metering roll-up and the never-decided retirement flag are untouched. The tenancy, RLS and audit rules are the existing rows'.

6. Data model

migrations/0072_meeting_bindings.sql, additive only:

Object Change
authoring_asset published_meeting_type_id uuid NULL REFERENCES meeting_type(id), CHECK (published_meeting_type_id IS NULL OR kind = 'policy'), partial unique index on the column
governance_body meeting_type_key text NULL, CHECK (IS NULL OR btrim(...) <> '')
programme_cadence meeting_type_key text NULL, same blank check
meeting CREATE UNIQUE INDEX uq_meeting_cadence_instance ON meeting (tenant_id, cadence_slot) WHERE cadence_slot IS NOT NULL AND status <> 'cancelled'

No new table. No FK on a versioned key: the actions resolve the latest non-retired version.
