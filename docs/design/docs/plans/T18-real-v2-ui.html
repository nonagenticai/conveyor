T18 — The real V2 UI

Programme project: T18 · issue #559 (kickoff) and #562–#566 (the five sequenced delivery units).

Gate (SPEC_V2 §12 T18): a signed-in tenant drives portfolio → programme → project → work package, organisation → release → binding, procedures intake → publish, tools call → ledger, improve → kata → adoption, operations incident → postmortem, and the ADM phase rail from the app; every destination's spec asserts empty, error, happy and one refusal; the V2 coverage record reports exists only from a real route and its spec; no production screen renders a fixture.

1. Objective

Make the V2 destinations real screens in apps/web — the one Leptos CSR/WASM application, served by the same binary on port 8930 — instead of pages in the static design pack. The app already has 31 routes, 25 screen modules and 31 Playwright specs for the V1 surfaces. T18 adds the V2 routes around them, with the same shell, the same action registry and the same test harness; the design pack stays the public programme site at /design/ and the reviewed reference (D64). The programme measures the result from the app's route table and specs, not from the mock (D65).

No table, action or event is added. A destination whose owning slice is not built renders not yet live, names the missing action or slice, and waits, typed, on that slice.

5. Destination contracts

Each contract names the read path, the write path, the states and the spec. Read paths use the owning slice's existing actions or literal GETs; T18 adds neither. Write paths are POST /api/actions/{name}/invocations with the headers §10.5.4 names.

  • Organisation — reads industries.list, departments.list, jobs.get/list, job_releases.list, job_bindings.list, approval_policies.list, decision_policies.list, refinements.list, laya_configs.list, ladder.list; writes the create/update/release/retire verbs those families expose. Empty = no departments; denied = no organisation:read. Spec: organisation.spec.ts.
  • Procedures — reads procedures.get/list, capabilities.get/list, the process map and the published pack; writes procedures.create|update|publish|retire, procedures.ingest_*, procedures.validate|review_source, capabilities.design|publish. An unreviewed SOP-derived procedure refuses publication (409); an unpublished pack refuses (409 procedure_not_ready). Spec: procedures.spec.ts.
  • Authoring — reads authoring.assets, the draft queue and dependency status; writes authoring.intake|draft|review|publish. A draft whose asset is unpublished refuses 422 asset_dependency_unpublished. Spec: authoring.spec.ts.
  • Portfolio — reads the computed project/programme set, programme_config.get, project_dependencies.list, cadences.list, metrics.programme; writes project_dependencies.*, programmes.update, wbs.*/baselines.* where the Plan owns them. A dependency cycle is refused. Spec: portfolio.spec.ts.
  • Programme — reads programmes.list|get, benefits.list, benefits.link_list, tranches.list, tranches.review_list, stakeholders.profile_list; writes the create/update/ transition/review verbs. A benefit without baseline, target, method or owner is refused; a transition that never measured its baseline cannot report realised. Spec: programme.spec.ts.
  • Architecture — reads architecture.artifacts_*, repository_search, contracts_list, profile_get; writes artifacts_create|update|approve|supersede|link, contracts_request|approve, phases_advance, reviews_record|waive, board_*. A phase missing a mandatory artefact is refused; a waiver needs an owner and a review date. Spec: adm.spec.ts.
  • Plan — reads wbs.*, baselines.list, registers.*, project_dependencies.list; writes wbs.*, baselines.take, registers.*. A change without a rationale is refused (422 change_rationale_required); a new baseline does not move existing run pins. Spec: plan.spec.ts.
  • Improve — reads the coach queue, kata.list, lessons; writes coach.triage|remedy|escalate, kata.open|observe|analyse|propose|measure|adopt|propagate|close, lessons.propose|review|promote. A kata without an instrument and a success threshold is not opened; a lesson with one evidence reference is refused. Spec: improve.spec.ts.
  • Operations — reads incidents, runbooks, the on-call roster and the ops read actions; writes ops.incident|triage|mitigate|resolve|postmortem and the gated ops.k8s_* set. A destructive action without the configured approvals is refused; a host action is refused until T7's mechanism exists. Spec: operations.spec.ts.
  • Tools — reads tools.list|get, toolkits.list, tool_bindings.list, tool_calls.list; writes tools.probe|call|publish|retire, toolkits.import_openapi|publish, tool_bindings.create|update|retire, tool_authoring.*. A binding that widens its grant gets 403 tool_effect_forbidden; a failed probe unbinds new runs (409 tool_not_ready). Spec: tools.spec.ts.

6. The delivery view

One read model at four levels: L1 the portfolio Gantt of programmes and standalone change initiatives; L2 a programme's projects grouped by tranche with the benefit and capability rails; L3 a project's kanban of work packages and loose cards; L4 a work package's own board. A bar is actuals — first observed card or run activity to completion, or to the snapshot time while in flight. A planned window is a dashed track only when meta.plan_start and meta.plan_end both exist; a row with no dated activity says so. Spend is the ledger's tokens plus the pinned commercial price; an unpriced row renders —* with its count, never $0. The public boundary is the tenant portfolio; the app shows the signed-in tenant's rows. The read model is the same derived work/measure/programme sections the public pack publishes, exposed by the owning slices' read actions; a section with no action is acceptance-blocked-by that slice.

8. Acceptance gate

The §12 T18 gate, proved by the five units together: every destination route exists, every destination has its spec, the V2 coverage record reports exists from real routes and specs, and the T12 loop runs from the app. A unit's own gate is its spec plus web.yml; the project closes when all five are merged and the coverage record has no destination new/extend without a named owner.
