5.6 Rendering — as built (2026-11-08)

Revision + view → crates/render → SVG, then PNG and PDF from that SVG. resvg 0.45.1 rasterises the usvg tree and svg2pdf 0.13.0 converts the same tree, so all three formats are encodings of one parse and cannot disagree about the page. ⚠️ This replaces typst, which was in this plan until B2: typst re-lays the page from different input (a second layout, and a class of bug no byte test can catch when the two paths never meet) and would have added ~130 crates to a workspace whose target/ was already 24 GiB. XMI via quick-xml.

Determinism contract: fixed (revision.content_hash, view.id, format, RENDERER_VERSION) ⇒ byte-identical output, proved two ways — checked-in golden bytes, and rendering in two separate processes and comparing. SVG ids are e-<uuid> / r-<uuid> / v-<uuid> / o-<uuid> / c-<uuid> and markers m-<kind>, never counters or map order; collections sorted; no timestamp, hostname, path or hash iteration. The PDF carries no date and no file id (measured: svg2pdf writes exactly one document-info field, a constant producer).

Page: one view is one A4 landscape page — canvas 1122.52 × 793.70 px at 96 dpi. Those two decimals are load-bearing: it is 297 × 210 mm ÷ 25.4 × 96, so the PDF page is exactly 841.89 × 595.28 pt (measured MediaBox [0 0 841.89 595.275]); rounding to 1123×794 makes the page 0.13 % oversize and a printer rescales. The diagram is fitted into a 24 px margin, centred, and never magnified above 1:1.

Fonts: the four DejaVu Sans 2.37 faces vendored at crates/render/fonts/ (from RM's own vendored set) with LICENSE and SHA256SUMS, registered from include_bytes! into usvg's fontdb. ⚠️ No mono face — the renderer draws labels and kind captions, never code, so DejaVuSansMono.ttf had no consumer. ⚠️ The original claim here — "load_system_fonts() does not exist" — is FALSE and is corrected: fontdb's fs feature is enabled transitively by svg2pdf, so the function exists whatever this crate declares. Host fonts are kept out by two guards instead: usvg/resvg are pinned default-features = false (so usvg's system-fonts feature is off and the parser never scans the system itself), and a source-scan test in crates/render/src/font.rs fails if any production line calls load_system_fonts — the "CI grep" this section asked for, running in the gate. A second test asserts the database holds exactly the four vendored faces. A character outside the face's cmap is a refused render (MissingGlyph), never tofu.

Layout: authored geometry wins — a view's stored view_object.bounds and view_connection.bendpoints are drawn as stored, and a connector takes the kind of the relationship it names (so a composition gets its diamond). With no view (view_id absent) or a view with no objects, crates/domain::model::layout supplies kind-banded rows ordered by (kind, id) — not (position, id), which this plan said and the model never had: model_element has no position column.

5.7 XMI

ArchiMate: Open Group 3.2 Model Exchange File Format subset over XMI 2.1. UML: XMI 2.5.1. Out-of-profile constructs increment unsupported[] and are skipped — never silently dropped, never fatal.

"Full conformance is infeasible" means: no MOF/EMOF completeness; no profile/stereotype definitions (UML Profiles, SysML, Archi specializations); no vendor extensions beyond meta.archi; no Difference/Copy/Document envelopes; no UML diagram interchange; unknown namespaces preserved as text.

Guarantees instead: (a) every in-profile element/relationship appears exactly once, with an XML id derived from its UUID — ⛔ prefixed, e-<uuid> / r-<uuid>, not the bare UUID this plan originally promised: an xs:ID/NCName may not start with a digit and a UUID usually does, so a bare one is not a legal XML id at all. RM's own exporters hit this and prefix (_ in tools/uml/xmi.py, id- in tools/architecture/exchange.py); (b) re-import into a fresh model yields an identical canonical multiset of (kind,name,documentation,parent-path) and (kind,source-path,target-path) — ids are not part of the multiset, which is why a foreign id can be mapped without breaking the guarantee; (c) re-exporting what was imported is canonically equal to the first export, not byte-identical — ⚠️ this plan said "byte-identical" and that is unachievable: the store mints a fresh uuidv7() for every imported row (NewElement carries no id), so the e-<uuid> in the second export necessarily differs. Byte identity holds where it can: two exports of the same snapshot are identical; (d) unsupported[] is returned by the action and carried on the import's model.created event.

Ids on import. An id that strips to a UUID is preserved verbatim. Anything else — an Archi export writes id-1a2b3c, RM writes _<uuid> — is mapped through Uuid::new_v5(CONVEYOR_XMI_NS, raw), so importing the same file twice yields the same ids within the document and a foreign document is importable at all. A duplicate id is refused (422); so is a <!DOCTYPE> (the parser never resolves an entity, and the document is untrusted input), a document over 1 MiB, and nesting deeper than 256.

What the codec deliberately does not carry (each is reported, never dropped in silence — measured against the pinned archimate3_Model.xsd and RM's own writers):

construct decision why
ArchiMate concept containment (parent_element_id) reported as Unsupported{element} ElementType extends ConceptType only — the 3.x exchange format has no nesting slot. RM reports the same loss as CONCEPT-PARENT. UML nests natively and round-trips.
ArchiMate view kind other than archimate_view exported as a diagram, kind change reported the format has one Diagram type
UML diagrams carried in one xmi:Extension extender="conveyor" no diagram interchange in this scope; bounds/label/position/bendpoints survive
aggregation / composition in UML both uml:Association, distinguished by aggregation="shared"|"composite" on the part end that is what UML means by them
include / extend / message in UML directed packagedElement with client/supplier the model has no interaction layer; the kind stays in xmi:type
foreign constructs (ownedAttribute, organizations, …) ignored, not reported Unsupported.construct is defined as element/relationship/view/object/connection only — a deliberate scope line

⚠️ Two XML facts the implementation had to learn, recorded because both produced silent corruption first: quick-xml 0.42 escapes attribute values itself (Attribute::from calls escape_attribute), so escaping by hand double-escapes (&amp;amp;); and it emits Event::GeneralRef for entity references rather than folding them into Text, so an undefined entity must be refused explicitly. Also: matching attributes by local name is unsafe for UML — xmi:type and type both reduce to type on an ownedEnd; match the exact name first.

5.8 Validation

models.validate enqueues job(kind='model.validate', dedupe_key='model:<id>:<content_hash>') after commit; the job writes one model_validation_run. Checks: kind in-profile; relationship endpoints legal; parent/child legality; view connection's relationship exists; a principle/requirement element's meta.governed_asset_id resolves in-tenant with the same title. Findings: [{code,severity,element_id?,relationship_id?,pointer,message}]. Write-time: an out-of-profile kind is 422 problem+json, type=/problems/model-profile-violation, errors[] naming kind and profile version.

Part A is 33 + Part B 35 = the front-matter's 68; import_xmi creates a revision in one transaction.

As built (B2). The three exchange actions live in crates/actions/src/model/exchange.rs and reuse model:read / model:write — no new scope. Their payloads follow CONTRACT §6: models.render returns content_b64 + media_type + content_sha256 + byte_len (cap 8 MiB), models.export_xmi returns the xml text itself (cap 4 MiB), and import_xmi caps its input at 1 MiB — the action request body is axum's 2 MiB default and JSON inflates, so a larger document would fail at the transport before reaching the codec. import_xmi writes a draft revision (write_head_revision_tx), never a published one: an import is not a publication, and publishing here would point model.published_revision_id at a graph nobody reviewed. (models.compare itself takes any two revision ids — it does not filter on status, so comparing the imported draft against the published revision is exactly how you see what the document would change.) models.render and models.export_xmi emit model.exported; models.import_xmi emits model.created.

Byte routes, not actions. GET /api/models/{id}/render?view_id=&format= and GET /api/models/{id}/xmi serve the same bytes with the real media type and an ETag equal to their SHA-256. They exist because a browser <img>/download cannot POST an action or send a bearer header (the dev-auth cookie covers them) and they have no MCP projection. They call the same conveyor_render entry point, so a route and an action cannot disagree.

5.12 Retention producers (added in B2)

§2.4's "model revisions keep the last 50" and §5.3's "model_validation_run kept 90 days" were rules with no producer — both tables grew without bound. B2 ships them as job kinds beside event.prune/job.prune: model.prune (25 3 * * *) and validation.prune (35 3 * * *), in crates/store/src/prune.rs, plus migration 0010 which re-creates model_validation_run_revision_fk as ON DELETE SET NULL — without it a revision prune fails the moment a validation run names a revision older than the 50th. 0009 is not edited: sqlx records a checksum per migration, so editing a shipped file breaks every migrated database.

8. Traps

  1. RM's table sprawl. modeling_models, _model_revisions, _publications, _reviews, _change_sets, _validation_runs, _validation_findings, _trace_links collapse to model + S03 revision + model_validation_run(findings jsonb) + S03 trace_link. Change set = one transaction; publication = revision.status='published'; review = S03 approval.
  2. entity_version_history has no tenant_id. Do not carry the table or its RLS carve-out; revision is tenant-scoped NOT NULL.
  3. JSONB geometry, not hit-testing. view_object.bounds is allowed (§5: read whole with the view), but nothing may WHERE bounds->>…; hit-testing, culling and overlap checks parse the rect in Rust. A measured hot predicate turns bounds into four generated numeric columns.
  4. Fonts are a dependency. An empty container renders tofu and a base-image change silently changes every golden PNG. Vendor the faces, never call load_system_fonts(), fail on a missing glyph.
  5. SVG ids must be deterministic. Map iteration or a counter renumbers per run and churns snapshots; ids derive from uuids, collections are ordered.
  6. Validation inside the mutation transaction holds the model lock for a full graph check and could roll back a legal edit. Post-commit job keyed on (model_id, content_hash).
  7. Do not trust an XMI file. Disable DTD/external entities in quick-xml, cap size and depth; a duplicate xmi:id is 422.
  8. The registry is not the profile. registry.json says what ArchiMate permits; the profile says what this app accepts. Using the registry as validator makes the gate vacuous.
  9. ⛔ An XML id may not start with a digit, and a UUID usually does. xmi:id="<uuid>" is not valid XMI — RM prefixes _ and id- for exactly this reason. Every id is e-/r-/v-/o-/c- prefixed and stripped on import; a foreign id is mapped through UUID v5 so the file still imports deterministically.
  10. ⛔ Deterministic bytes are not the same as a right picture. The first golden render was byte-stable and drew a view connection as a plain arrow because the renderer never resolved relationship_id to its kind. A golden test cannot catch that class of defect; only looking at the image (or asserting the marker) can. Assert the semantics you can — the composition marker, the two-layer colour, the connector's kind — not only the hash.
  11. ⛔ svg2pdf writes one document-info field and no date, but prove it. The determinism claim rests on pdf.document_info(id).producer(TextStr("svg2pdf")) being the only thing it sets — verified in 0.13.0's source, and measured by rendering in two processes. If it ever gains a timestamp, the PDF must become normalised in the contract; hand-editing PDF bytes is not an option, because changing them shifts every xref offset.
  12. view_object.position is numeric → f64. Sort by (position, id) and never print it into the document: a float's printed form would become part of the byte contract.

9. Decisions closed here

  1. One model shape, language discriminates; no per-language tables.
  2. Profiles are curated and versioned — ArchiMate 30 + 11, UML 10 + 9 with five diagram kinds; registry.json supplies labels/icons/edge hints only.
  3. Profile membership is decided by consumers: live RM data > fr render map > the standard.
  4. Principles/ADRs stay S07's; S08 adds no action or table. A principle/requirement element carries meta.governed_asset_id — the asset owns the lifecycle, the element the drawing.
  5. TOC tables stay S07's; S08 ships actions only.
  6. Publication is a revision status; change sets are transactions; reviews reuse approval.
  7. Rendering determinism is a contract keyed on (content_hash, view, format, renderer_version).
  8. XMI is profile-scoped with stated guarantees; unsupported constructs are reported, never a reason to widen the profile.
  9. Portfolio registers are one table with kind; deliverables and milestones one table with kind_code.
  10. architecture_containers is dropped; queue selection is S06's card-type×list.
