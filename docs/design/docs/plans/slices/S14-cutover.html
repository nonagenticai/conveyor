S14 — Cutover

Programme project: S14 · issues #18, #44

8. Traps

  1. The archived repo owns the name. gh repo create returns 422 while nonagenticai/conveyor exists (measured archived=true, pushed_at 2026-10-29). Rename, do not delete.
  2. fr.nonagentic.ai is still live and serving. D16 keeps the host with the old app until decommission; there is no DNS switch. Re-pointing it early is a split-brain, not a cutover.
  3. Stranding the agent platform. One URL + one secret under two names; the MAC is over raw bytes, so a re-serialising proxy 401s everything (±300 s skew likewise). Use the in-cluster URL, not the Cloudflare host.
  4. Deleting a DB before its dump. D7 discards the data; it does not license dropping a database that was never dumped and restore-tested.
  5. pg_dumpall runs on master (02:40 UTC, retain 3) — it is not a cutover dump, and a dropdb on master propagates to mf1's streaming standby the moment it commits.
  6. The freeze is a rule, not a mood. A "quick fix" to fr/RM/Planka during S14 goes in freeze-log.md and is absorbed or dropped.
  7. The ext_authz allowlist is an enumeration — do not add the conveyor host to AUTH_REQUIRED_HOSTS.

9. Decisions closed here

  1. The archived repo is renamed to conveyor-archive, never deleted; George authorises, the session executes with GH_SHIM=off.
  2. Warm window = 14 days; the point of no return is dropdb, not the switch — scaling and re-pointing are reversible, dropping is not.
  3. Cutover is host-parallel: conveyor.nonagentic.ai is new; fr.nonagentic.ai is retired only at decommission.
  4. The channel base URL is the in-cluster service address; the secret is rotated at T0 and both names are changed in one commit.
  5. A pre-deletion dump is mandatory evidence (three -Fc dumps, restore-tested) even though D7 discards the data.
  6. Rehearsal evidence is numbered R1–R4, cutover R5–R7, under docs/cutover/evidence/.
  7. The andon gate is the conveyor's andon_state; it does not rely on the fr UI, which is gone.
  8. Freeze date = the SPEC approval date (2026-11-07); freeze-log.md starts there.
  9. The legacy n8n deployment stays idle, undecommissioned (flows died at S13; DB dumped at T+14).
