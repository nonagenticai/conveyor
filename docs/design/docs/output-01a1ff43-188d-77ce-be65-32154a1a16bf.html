Spec — SPEC-V2 (retrospective, 2026-11-26)

Context

V1 built one Rust application that carries work: projects, boards, lists, cards, runs, approvals, procedures, capabilities, capability agents, knowledge and memory bindings, an inference ledger, a native SWE-bench harness, evals and the compiled-prompt pipeline. Its last whole-tree checkpoint of 2026-11-09 measured 83 tables and 243 actions as a floor, and the app is live at conveyor.nonagentic.ai on main 85487a04, 3 pods, with /health and /health/ready 200 on :8930 (deploy record 2026-11-10). V1 answers how work is carried; it does not answer who the organisation is. Three independently built things — the agent platform as a user of the conveyor over MCP, the KH hierarchy proving positions, departments and immutable releases, and the conveyor's own work and proof rows — have arrived at the same shape, and the missing piece is the organisation. The field builds agent conversations; real organisations run on positions, work products, gates, baselines and evidence.

Requirements

The requirements are the plan's hard invariants and its binding decisions. One record per fact: no concept is stored in two systems, and systems join by pinned reference. No work without a card; no transition without an action; no completion without evidence. The executor never approves its own work, and dual control is two or more distinct approvers. Rule → laya → generation → human: an LLM never selects, routes, classifies or approves, and a generated output is a draft with no path to a state transition. Every model call is ledgered and budgeted; an unresolved binding, pack, prompt source or tool fails closed with 409 *_not_ready before the first call. No speculative aggregate: a table exists because a named procedure uses it and a metric reads it. Tenant configuration over code: every policy, threshold, limit and approval kind is a versioned tenant-scoped row with a platform default. Requirements are typed condition, constraint, assumption or delta and are managed continuously, not by phase.

Design

The design has four units and nothing else: a job (a position — a capability, a procedure, an inference configuration and an authority), a card (a work package), an approval (the one human-escalation primitive, where a question is an approval) and a run (one recorded attempt). Departments, programmes and portfolios organise them; knowledge, memory and tools configure them; evals, benchmarks and the ledger measure them; a meeting is a decision forum over them. The organisation spine is industry → department(s), ordered → job, with knowledge layered base → industry → department archetype → each department in order → job, compiled into an immutable release; a binding pins job_key, release_hash and a release_snapshot, and a retired binding refuses 409 job_binding_stale before any model call. The work hierarchy is tenant → portfolio (computed, never a row) / programme (shared_config plus project dependency edges) → project → WBS → card → run → step. TOGAF ADM, SAFe, PMP and MSP are rows and gates: phases are WBS nodes, artefacts are typed rows with entries and links, gates are approvals, tranches are the programme's management unit, and a benefit without baseline, target, method and owner is refused. The tool estate is a catalogue of immutable toolkit versions, a binding with an effect ceiling and one tool_call row per call, all through one in-process broker; bytes go directly to MinIO under tenant prefixes.

The seven A–D artefacts are approved rows published 2026-11-22 and the eight E–H artefacts are authored on 2026-11-26; the Phase-G review records level compliant; the project re-closes through the one gate with an approver other than its requester. The plan's own slice acceptance is narrower and testable: T0 proves that a job is created, a release published, a binding pinned and a run on a retired binding refused; later slices each carry a named refusal. No TOGAF certification, SAFe compliance badge, PMP certification, MSP conformance or full ADM conformance is claimed, and that restraint is part of the acceptance.
