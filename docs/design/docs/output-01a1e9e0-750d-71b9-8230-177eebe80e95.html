Row gaps

The map is only as good as the rows beneath it. Two gaps are named rather than hidden:

  • B1's row is incomplete. It carries the four fields the completeness rule requires (baseline, target, measurement method, owner) but not the path levels (objectives, capabilities, observable outcome, project): the row was created before those levels were populated, and the service has no benefits.update action. The B1 path below is the profile's, pending a row update when the action exists; the gap is a kata candidate.
  • B-PROBE is a probe row, created while testing the completeness rule. It is not a benefit and is absent from this map by intent; it is disclosed on #260 for retirement by a cleanup migration.

Dependencies

  • B1 depends on T2 and on T0's decision schema; a gate that never refuses invalidates it.
  • B2 depends on T13 and the absorption sequence; an unabsorbed service is outside the ledger.
  • B3 depends on T6, T3 (the PM job) and T1; the CI queue is the delivery risk.
  • B4 depends on DESIGN-PUBLISH and the public repository; the contribution path is live.
  • B5 depends on T0; a second store is the disbenefit the gate refuses.
  • B6 depends on P0 and T1; plan drift is the failure mode, checked by the design-pack gates.
