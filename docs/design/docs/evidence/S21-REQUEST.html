Issue: #624 · Branch: issue/624-s21-request · Date: 2026-11-23 · Baseline: origin/main@29cc3820

What this step builds

  • One request document per process-driven step — {step, action, action_text, input, outputs, on_result, gate} — rendered in the process (Request) section after the current-step line and passed unchanged to laya.judge as its case input.
  • The store reads the resolved run_step.input (persisted at claim) and the frozen process_step.outputs/action_text/gate_kind in one read. The compiler reads; it never re-resolves the template and never writes.
  • A synthetic run-level internal_agent agent.run step contributes none of its executor envelope; its Request is the release definition, as before. The run-level judge now receives that release request too.
  • The request is inside the compiled text, so it is inside prompt_sha256. Whole values; the section budget refuses with the measurement, never truncates. No migration.

Not this step

No card-driven run creation, no memory.remember write-back at handoff, no automatic apply of an L1-accepted draft, no budget mechanism (the #526 lane's), no prompt-budget authoring (v1-p77-2), no NULL-hash guard (v1-p77-1), no release pinning (v1-p42-1), no workflow-node request (a run_step with no process_step_id), no parent-run memory in a child's prompt, no UI, no PDDL storage, no second compiler, no migration.
