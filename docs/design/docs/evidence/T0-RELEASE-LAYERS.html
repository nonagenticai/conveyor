Issue #697 · branch issue/697-s21-execution-loop · ADR 0020-release-knowledge-layers · CONTRACT §30 · S21 §23 P4 · migration 0072 · resolves rework v1-w1a-2

State: built. Measured on 2026-11-24 at the code of b7722710 (the suites at 54c51a63), before the PR. The merge is the lane's last CI run; nothing here is claimed for main yet.

What changes at this level

Before: compile_release_tx built the release snapshot from job_catalogue.definition, the industry and the placement rows. No code read a knowledge layer, so an unresolved required kind could not stop a publish and two sibling departments could disagree silently; neither release_not_ready nor department_conflict existed anywhere under crates/.

After: migration 0072 adds organisation_layer (base, industry, department archetype, each department in declared ordinal, job). The publish resolves each kind in that order, tightens required downward only, refuses 422 department_conflict for disagreeing siblings unless a job-layer row resolves it, and refuses 409 release_not_ready naming the kind and department when a required kind has no value. The snapshot carries every resolved value with its level and source key, sorted, so two identical publishes hash identically. organisation_layers.set|list author and read the rows; no new scope.
