Token spend per accepted deliverable — pre-transition baseline

Measured from the full-fidelity snapshot at ec799ee1 (2026-11-21T23:27:35Z, live tenant nonagentic, migration 67), built by the branch binary from the restored production copy. T5 landed on issue/526-u5a on 2026-11-22 but is not deployed, so this is the pre-transition baseline.

Definition

An accepted deliverable is a published output document attached to a project — artefacts.json.documents with publishable = true. The snapshot has 145. The ratio is portfolio-level, not a per-run causal attribution: a run may produce no output, an output may predate the inference ledger, and project/card attribution exists for only 3 projects and 5 cards. The post-transition measurement must use the same definition over a window at least as long.

Why this is a ceiling, not a cost

366 of 371 runs failed. The tokens were spent overwhelmingly on work that produced no accepted deliverable. A per-deliverable improvement that simply rejects more work would look good on the primary ratio and bad on the secondary one; both are therefore recorded.

The frozen a33e6562 pack reported 165 outputs; this fresh snapshot reports 145. The fresh snapshot is authoritative — the frozen pack's outputs projection was incomplete.

Proposed target (owner confirmation required)

  • ≤ 52,185 tokens per published output (−20% against the baseline).
  • Run failure rate ≤ 20%, measured over the same post-transition window.

The six live benefit profiles currently say "not measured — no instrument exists". The token KPI is not yet one of them; U6 must add or amend a profile and record the target and the post-transition measurement at the same measured_at as this baseline. The committed data is docs/evidence/benefits/token-spend-baseline.json.
