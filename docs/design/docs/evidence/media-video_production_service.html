A measured defect in the live reference

POST /api/compile cannot complete in the running digest. Every submission dies in _initialize with AttributeError: 'CompilationJob' object has no attribute 'fps' — the image's ORM lacks the column — so the job stays processing forever. Production runs this exact digest. What is pinned is therefore the intake contract (the 200 AsyncJobResponse), never a completed compile. The port does not claim a render parity the reference cannot produce; its own media.produce_video tests carry the render evidence.

Declared deviations

  1. Recording is virtual-time sampling, not a wall-clock screencast. The reference records a live Playwright context for the session's duration. The port renders the page at successive --virtual-time-budget values and encodes the frames with ffmpeg: deterministic, reproducible, and no new dependency. A page whose content depends on real network or real wall-clock time will differ from the reference; a deterministic page matches frame for frame.
  2. url recording is opt-in. A remote URL is refused by name (egress_denied) unless the request carries allow_network: true. P2.2 keeps egress denied by default; a deployment that wants URL recording grants it per kind (#83).

Boot traps worth keeping

Migrations are initContainer-only (head 012); the service reads API_PORT, not PORT; AUTH_ENABLED=false is ignored and the trusted lane still refuses a tenantless request; the licence gate's default is off; local storage plus COMPILATION_ALLOW_LOCAL_FILE_INPUTS=true is what makes a capture possible without an object store; the VP9-alpha probe passes at boot and Chromium starts lazily per job, not at boot.
