Reading: both renderers are vsync-capped at 60 fps on the reference scene, so the frame metric is a tie; canvas-2D has the smaller heap, needs no WebGL2/GPU, and is the smaller implementation. The soak shows no growth (the final heap is below the start). The wasm/ECS budgets — ≤ 600 KB gzip, ≤ 1 ms fixed tick, ≤ 5 000 entities — are not measured here; they belong to crates/walk-world and its W1d world spec. The runner is a Linux GitHub runner, not the M-series reference laptop; the protocol and machine class are recorded so a repeat is comparable.

What this closes, and what it does not

  • Closes the P0 client-contract gate: no unproven assumption (dev session, PKCE construction, schema forms, headers, refusal, SSE, deep link) enters P1.
  • Closes the renderer question: ADR 0023 selects canvas-2D; WebGL2 remains a candidate behind the WorldView port, not a dependency.
  • Does not prove production sign-in: the issuer is empty in the dev environment and the /walk/ redirect URI is an external registration. That scenario stays acceptance-blocked-by.
  • Does not prove the wasm/ECS budgets; W1a–W1d and the walk workflow will.
  • Does not replace the W2 foundation's real Portfolio write: the dev seed's programmes are empty, so the write proof here is the card create/move. The foundation creates or picks a Portfolio row and records its action.
