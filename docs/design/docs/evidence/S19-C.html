Step 14 — the health audit

  • crates/domain/src/eval/audit.rs — the six-section checklist as pure functions (Section/Severity/FindingDraft, InstrumentFacts, Controls, findings, resolution_line, resolution_shortfall) and unit tests.
  • crates/store/src/eval/audits.rs — eval_audit + eval_audit_finding rows: insert, get, list (keyset), a guarded status transition (queued → running → succeeded | failed), findings insert and a decide-once transition. A new EvalStoreError::NotOpen maps to 409 not_open.
  • crates/actions/src/eval/audits.rs — eval_audits.start|get|list and eval_findings.list|decide; start validates the eval, the version (same eval) and the optional target run (same eval and same version), writes the audit and one eval.audit.run job in the same transaction, and returns it queued. Decide records who/when and carries the note on the eval_finding.decided event (the finding table has no note column).
  • apps/server/src/eval_audit.rs — the job. It reads the version, its cases (and each answer key), its metrics, the target run and its results/attempts; runs the mechanical checks; runs the controls; writes the findings and the numbers; appends eval_audit.completed on eval:{id}. Controls: the oracle grades each case's answer key through every programmatic metric (presented both as the answer and wrapped as the subject's completion shape) and the null grades an empty answer the same way — the two numbers the oracle ≈ 100 % / null ≈ 0 % gate reads; the judge control feeds the first model-declaring rubric/pairwise metric an empty answer, an "I don't know" and a confident wrong answer through the real invoke → grade_from_judge path, and a score ≥ 0.5 on any of them is the judge_accepts_negatives finding. The resolution numbers come from the target run's held-out split (1/sqrt(n·reps) floor, binary headroom), and the floor_above_headroom finding fires when the floor cannot clear the headroom.

Step 15 — eval_runs.export (crates/actions/src/eval/export.rs)

No case column is selected, so the answer key cannot appear in the bundle — eval_roundtrip asserts the literal string "expected" is absent. Caps at 64 MiB (413).

Decisions worth carrying

  • Cost is priced from the recorded usage, not from inference_call. D23's amendment (inference_call.caller_kind='eval', eval_run_id) is specified and unbuilt; the ledger's only link today is action_invocation_id, which covers the subject call but not the judge. Report, audit and climb price eval_case_result.usage/judge_usage and eval_attempt_error.usage — one arithmetic across the three. Open item for the lane that lands the amendment: make the ledger the authority; a migration ≥ 0032 is needed because 0030/0031 are in flight.
  • The oracle presents the key in both shapes (the answer itself, and wrapped as the subject's completion body) because a programmatic grader reads either label or choices.0.message.content. It passes when either shape scores 1.0; the null passes only when neither does.
  • The judge control probes one metric, three calls. It is about the judge prompt, not every metric; three calls per metric would spend a run's budget on an audit. A call that errors is reported as judge_error and leaves the control unmeasured rather than counting an outage as leniency.
  • eval_runs.export requires evals:read (the slice's scope) but declares effect: write: it creates a document row and an object. The bundle's content type is application/gzip, which the documents.create allowlist does not carry — the export writes the document row directly and the download route serves the row's own type.
  • A finished audit is not re-run. A second delivery of the job returns before touching the findings; eval_audits.start is not idempotent and mints a new row per call.

Not built / known limits

  • The method's tier-3 per-case LLM auditor (a model call per case) is not built; the audit's mechanical checks are exhaustive over the case set and the model is used only for the judge's three negatives.
  • The report's metrics[] columns are whole-run; the held-out numbers are the per-split row (group_by: "split") and the noise_floor/headroom pair.
