What changes

  • A handover parks the run in waiting_approval; the executor approval names the draft.
  • approvals.decide records the L3 gate.draft_apply decision, settles the run running and enqueues run.resume; an executor gate refuses a machine decider in the approval writer.
  • run.resume applies the draft through the one hardened apply_draft_tx and finishes the run; it never calls the model.
  • ladder.record refuses a forged human rung or a pending approval; ladder.apply_draft requires the decision to name the exact draft (rework v1-w1c-2:T2).

Reversal evidence

The negative scenarios are the guard proofs; each names the guard it exercises:

  • remove the draft-binding check → an_unbound_decision_cannot_apply_a_draft would attach;
  • remove the prompt-hash/document check → a_decision_bound_to_another_draft_is_refused would apply the wrong draft;
  • remove the person check → a_human_decision_requires_a_person_and_an_approved_approval would record a service actor;
  • remove the approval-state check → that test's pending approval would resolve the decision;
  • remove the executor-gate writer check → an_executor_gate_refuses_a_machine_decision would approve a machine decision.

The guards were not separately deleted in a local run (no local Rust compilation); the negative tests are the standing evidence.
