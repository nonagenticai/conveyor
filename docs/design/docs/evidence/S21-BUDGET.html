Built

  • migrations/0031_s21_prompt_budget.sql — prompt.budget_chars and prompt_section.budget_chars (nullable = unbounded, > 0 by CHECK) and 'role' added to prompt_section.source_kind. Grants are re-applied by migrate (0030's rule); no grant block.
  • crates/domain/src/prompt.rs — PromptSource::Role; PromptSection.budget_chars and PromptDefinition.budget_chars; CapabilityFacts.intended_role; two refusals, SectionOverBudget { kind, measured, limit } and PromptOverBudget { measured, limit }. compile() stable-sorts sections by trust rank (instructions → procedure → capability/role → knowledge → project/card), measures each rendered block (heading included, .chars().count()) against its section ceiling, measures the joined text against the prompt ceiling, and only then hashes.   • crates/store/src/prompt.rs — the recipe read carries both budget columns; read_capability reads capability_agent.params and exposes params->>'role' as intended_role (empty when the binding declares none). params is existing editable config on capability_agents.create|update, so no action schema and no served-spec hash moves.

  • crates/actions/src/prompt/mod.rs — PromptError::BudgetExceeded { reference, section, measured, limit }, mapped to 409 capability_not_ready with field prompt_ref, code prompt_over_budget, and a detail naming the section (or the whole prompt) and both numbers.
  • No new action, scope, route, event or table. The served spec and served-spec.lock.json are untouched (the last settling lane writes the lock).

Independent audit

A fresh validator-deep that wrote none of this returned YES across the six claims (domain compile/trust order/budget/role, store round-trip + CHECKs, actions mapping, clippy). Its two non-blocking findings were closed before handoff:

  • the heading-inclusive measurement was not pinned by a mutation, so a future refactor could have measured only the body and silently loosened every section budget. The domain test now asserts measured byte-for-byte against body + "## Project and card\n";
  • the Some(section) arm of the action mapping was unasserted. prompt_compile now has a section-budget case that proves section == Some(System) and the detail names the section.

Re-measured after both fixes: domain prompt 6/6, prompt_compile 4/4, clippy clean.
