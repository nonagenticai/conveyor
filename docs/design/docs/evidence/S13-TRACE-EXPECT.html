What the gate proves — and what it does not

  • Proves: the re-authored flow executes the same ordered (node, effect, outcome) path as the recording, and (once the fixture test calls end_state_matches) reaches the declared business result.
  • Does not prove: payload-level equality across systems — by design; input_hash/output_hash remain in the trace for forensics and are compared only between two conveyor traces.
  • The three synthetic fixtures' end_state is {"terminal_effect": …} today. Real re-authored flows (steps 14–15) carry business keys (card list/status, decision, message refs); an empty end state is invalid.

Provenance note (caught by s13-trace-gate)

provenance.projection_sha256 is the canonical-JSON hash of the projected records, not of the recorded .old.jsonl bytes (those are pinned by fixtures/SHA256SUMS). The field was renamed from old_sha256 for exactly this reason: one name must not read as the other artefact.
