The walk's accessibility record (W7)

Measured 2026-11-28 for S4 (#817) against apps/walk at its head, using the documented local harness (the published server image + Postgres 18 + Redis, DEV_AUTH_TOKEN=dev:alice). The browser is Playwright's chromium; every number below is printed by the specs, not estimated.

Protocol

cd apps/walk
PLAYWRIGHT_CHANNEL=chromium DEV_AUTH_TOKEN=dev:alice npx playwright test e2e/a11y
  • e2e/a11y/keyboard.spec.ts — the skip link, a room sheet, Escape, focus return.
  • e2e/a11y/layout.spec.ts — the canvas as an image and out of the tab order; the palette as a keyboard path; 390 px and 200 % zoom with no horizontal scroll; the 44 px control target; the contrast ratio of ink on paper.

a11y.contrast={"heading":12.889,"body":6.146,"button":12.889}

The fix this record required

The first measurement found every control under the budget: .button 37 px, .map-room **34 px, .palette-row**36 px** — no minimum height inapps/walk/style.css. The SPEC's 44 px is not optional, so S4 adds min-height: 44px` to those three control classes and nothing else. This is a design-system change with a global effect, declared here and in the issue so it is reviewable: it changes no layout logic, only the minimum size of a control. The same spec asserts it from now on, so a regression fails CI rather than a later audit.

The one promise not met

The Palette button's title reads "Search routes and actions (Ctrl/Cmd + K)", and no handler for that shortcut exists anywhere in the client (grep -rn 'KeyK\|metaKey\|ctrlKey' apps/walk/src returns nothing). The palette is still a keyboard path — Tab and Enter reach it, proved above — but the advertised shortcut is a false promise. The shell is a parent-owned seam, so this is defect unit #914, not an S4 edit; its spec case lands with that unit.

Re-running

cd apps/walk && PLAYWRIGHT_CHANNEL=chromium DEV_AUTH_TOKEN=dev:alice npx playwright test e2e/a11y

The walk workflow runs the same specs on every PR and on every push to main.
