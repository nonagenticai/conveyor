The reversal proofs

  1. The split is immovable. a_climb_cannot_redraw_the_split records the version's split_sha256 and every eval_case.split, runs a round, re-reads both — identical — and then evals.draw_split answers 409 split_locked.
  2. The revert's reason is recorded. a_two_round_climb_keeps_one_round_and_reverts_the_other… — round 1 keep, round 2 revert / held_out_flat, on eval_run.summary, in the report, and reproduced by a fresh eval_climbs.get.
  3. No round before the plan. 409 plan_pending, then 409 baseline_missing, then the round.
  4. The analyzer never reads test. A round citing a test-split trace is 422 test_transcript_in_round.
  5. The noise floor is said out loud. 422 delta_below_noise carrying the measured floor.
  6. A gated round records itself and runs nothing. awaiting_approval, queued_jobs: 0.
  7. The paired delta reproduces by hand. a_paired_delta_recomputes_by_hand: scores a=[1,1,0,0], b=[1,0,1,1] ⇒ both 1 · a_only 1 · b_only 2 · discordant 3, exact McNemar 2·(C(3,0)+C(3,1))/2³ = 1.0, delta 0.25, CI [-0.688278, 1.188278] (sample SD √(2.75/3)). compare_refuses_two_versions_or_graders_or_splits is the other half: a second version is 409 not_comparable.
  8. A fourth content round is refused. a_fourth_content_round_is_refused: three flat rounds, 422 buckets_required on the second, a buckets round accepted, 409 content_round_refused on the fourth. no_round_without_registered_gates is the cost twin: no hold ⇒ 422 at start, the floor on the plan, 409 plan_pending before it is signed, 422 lever_order when a round skips the staircase.
  9. A regrade is a new run and never re-invokes the subject. a_regrade_grades_the_stored_output… — the same stored output scores 1.0 under v1's key and 0.0 under v2's, with the source's model/latency/action_invocation_id and an empty usage (the subject was billed once).

Defects the execution found (each would have shipped silently)

Part A's six are in the git history of this lane; the five from Part B:

  • The stall gate could not fire. A categorisation round reset the flat streak, and the mandatory buckets round fires at streak 2 — so no streak could ever reach 3 and content_round_refused was unreachable. The slice counts the categorisation as one of the three rounds that did not clear the band; it now increments instead of resetting.
  • A cost climb measured no cost. Spend and hold readings were collected only from rows carrying the target's grade — and a cost_usd climb has no cost_usd grade key. Every cost round saw cost 0 (reverting cost_not_cleared) and the guardrail passed vacuously, which is the one thing it exists to stop.
  • The cost staircase never moved. Goal::advance_lever was implemented and domain-tested but never called, so a cost walk asked for caching_health on every round. It is now derived from the kept rounds — incrementing in place would advance twice on a re-settle.
  • The cost walk's winner was chosen by quality. All held-out means are 0 for a cost goal, so "highest test score" silently named the first kept round; a cost goal now names its cheapest kept round.
  • eval_climb.round_completed fired only at stop. persist_decisions was called only from stop, so a live consumer saw nothing between round 1 and the report. round now persists and announces the rounds it settles (idempotent on the stored decision, so it emits once each).

Plus one the regrade forced: the tick counted only eval.case.run (outstanding_jobs_tx), so a regrade run would have been finalised void/partial before its first job ran. And one the regrade needed: the transcript stored only the answer text, while graders read paths into the whole output — a regrade from that would have scored a different value. The assistant turn now carries the raw output (≤256 KiB; a larger output is graded but not regradable).

Owner rulings encoded (2026-11-09)

  • One active climb per eval; a later climb continues the variant numbering.
  • The report is eval_climb.narrative_md (migration 0029).
  • eval_runs.regrade is evals:approve: it creates a run and can spend a judge call — the same budget decision eval_runs.start makes. The compiled kata_executor default keeps it.
  • A regrade onto the source's own version is refused 409 version_unchanged: a regrade carries stored outputs onto a new instrument. Consequence, and the reason the refusal is sharp: compare refuses two versions, so a grader fix is regrade every arm, then compare new-vs-new — never a new grade against the run it replaced.
