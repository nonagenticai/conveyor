The walk's slice-gate audit (W6)

Measured 2026-11-28 at main@8430123a782d02907332acd5fc964561a2a4abc9 for S4 (#817), against the 56-route census (docs/evidence/walk-census.json) and apps/web at the same sha.

1. The rule

docs/plans/GEMBA-WALK-SPEC.md §14: a destination may not claim to be implemented from its route alone, and a capability the server lacks is the honest gate — never a fabricated surface. The plan's W6 asks a narrower question: does every gate the walk renders match what apps/web renders at the same sha, and is every difference owned by a slice or a recorded decision?

Two kinds of non-live state are possible, and they are not the same thing:

  • a role gate — the action is absent from this role's manifest (ctx.hasAction(name) is false). It is derived at runtime and cannot drift from the app, which gates the same way.
  • a slice gate — the capability does not exist yet for anyone, so the screen says so in prose.

4. The three non-manifest conditions

measure.js:57 — the instruments list is filtered by hasAction, and an empty result renders "Measure is planned". The app does the same: apps/web/src/screens/measure.rs:51-53 returns an empty vector when metrics.usage is absent. Match.

copilot.js:56-62 — the screen reads /api/copilot/actions; when the route is absent it names the S10 slice and says it will not invent a conversation. The app has a live chat transport (apps/web/src/screens/copilot.rs:3, POST /api/copilot/conversations). Deliberate divergence, sanctioned by GEMBA-WALK-SPEC.md §15, which lists chat as a non-goal for the walk. It is recorded here so it is a decision, not an omission; if the owner ever lifts that non-goal, this is the file and the line that changes.

sources.js:162-164 — an empty asset read names T16/T17 in prose. The read itself is gated on authoring.assets and the app's sources.rs:41-45 performs the same empty read. Match; the slice names are prose, not a promise.

5. The empty-read convention

apps/web substitutes an empty list when an action is absent or unauthorised: measure.rs:51-53 (metrics.usage), sources.rs:32-34 (capabilities.list) and :41-45 (authoring.assets), plan.rs:41-52 (wbs.list, baselines.list, registers.list). The walk does the same in nine destinations (listed in §2). This is parity, not a defect: the walk's rule is "the same read contract as apps/web", and a divergence toward a stricter gate would be a visible difference between the two clients rather than an improvement. It is recorded so the next session does not re-litigate it.

7. Compliance statement

Every non-live state the walk renders is either (a) a runtime manifest check, which cannot drift from the app because both read the same manifest, or (b) one of the three conditions in §4, each compared with apps/web at the sha and either matching or recorded as a spec-sanctioned divergence. No slice gate is unowned, and no destination claims a surface the server does not have. The two S4 routes (/boards, /card/:card_id) have no non-live state; their writes are hasAction-gated.
