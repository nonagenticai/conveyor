The four reversal proofs

  1. A failed attempt never writes the slot. eval_runner::a_failed_attempt_leaves_the_slot_empty_and_the_retry_fills_it — a 5xx leaves eval_case_result empty and one eval_attempt_error at attempt 1, failure_class='serving'; the retry fills the slot and the error row survives.
  2. The refusal names every gate. eval_runs::start_names_every_missing_gate_in_one_answer — 409 eval_not_ready naming eval_inputs, eval_grading, metrics, split_missing in one reply, and no run row written.
  3. The machine is walled twice. eval_heldout::an_agent_reads_the_instrument_but_never_the_held_out_half — the agent's six tools answer 2xx; eval_results.get is refused by the allowlist (action-forbidden) before any row is read; a human member reaches the handler and is refused by scope (held_out_split, naming evals:approve) on test and allowed on train; the owner reads the test transcript and still never sees expected.
  4. A second start is a resume. eval_runs::start_enqueues_one_job_per_case_and_rep_and_a_second_start_resumes — the same run id, queued_jobs = 0, and the job count stays at cases × reps.

Defect found by executing (and fixed)

apps/server/src/eval_worker.rs::tick set complete/partial directly from queued. The domain's table admits only queued → running, so the tick raised an eval run cannot transition from queued to complete and the run could never finalise — reachable whenever every case lands before the first tick sees the run. The tick now makes the queued → running step first. Proved by eval_jobs::the_tick_heartbeats_while_work_outstanding_and_finalises_when_it_is_not, which failed with that exact message before the fix.

A smaller one, also fixed: the driver's judge_is_subject refusal reached the evidence row as prose only. It now carries the machine code, because that is what an operator greps.
