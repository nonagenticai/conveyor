  • The empty-leaves defect: pack_leaves returns Ok(vec![]) for a published-but-empty pack; the old guard passed it. pack_state now treats emptiness as pack_not_published (CONTRACT §17's "no resolvable leaves").

Known limits

  • Readiness is a LIVE external check for required packs: capabilities.get holds its transaction across up to one pack_leaves call per required binding (the start guard already did). The action budget is 30 s (raised from 15 s to match procedure_runs.start); a tenant with many required packs would need a bounded loop, not a larger timeout.
  • blocking[] is the GET's field name; the 409 carries the identical Vec<FieldError> in the API-wide errors[] envelope (CCR 1, S15 §13). There is one producing function.
