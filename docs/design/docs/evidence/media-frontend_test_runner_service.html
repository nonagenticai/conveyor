The one absorbed kind, and the contract it changes

The reference's POST /api/test-runner/execute accepts a Playwright suite: a ZIP package_url or a bdd_job_id pointing at the retired bdd-playwright-service, plus suite knobs (browsers, workers, grep_pattern, expect_recording) — and screenshot_on_failure was accepted and ignored. ADR 0007 §1 gives the browser image a native Gherkin runner, so the kind takes the feature document itself (feature + target_url) and keeps only timeout_per_test_ms and retries. screenshot_on_failure is either implemented or omitted, never accepted and ignored again; the suite and recording fields are refused by name.

Declared gap: the step vocabulary is navigation and assertions, executed with the image's own Chromium (--dump-dom). Interaction steps (click, type, scroll, hover, upload) are refused by name with step_not_supported until this image carries a CDP client — the one dependency the workspace does not have and this unit did not add. trace_on_failure is refused for the same reason.
