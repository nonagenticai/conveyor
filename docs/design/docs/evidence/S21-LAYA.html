State: skeleton. The measured scenarios, reversal proofs, test counts and residuals are filled at completion, from the exact head, like docs/evidence/S21-APPLY.md and S21-HANDOFF.md.

What changes at this level

Before: ladder.evaluate took answer, confidence, latency_ms and probabilities from its request body and wrote rung = 'laya', so any governance:write caller could record a calibrated-looking L1 decision it had invented; options were inline request text; an outage could not become gate_unavailable.

After: the ladder builds the case from the effective policy and an authored option set; the engine performs the request as the external action ladder.precheck; ladder.evaluate records a decision only from the engine's recorded exchange (input-hash equality, 2xx, measured duration), and an unavailable answer follows the policy's fail action.

Reversal proofs (fired, red, reverted, green — filled at completion)

  1. Accept a caller-supplied confidence again → a fabricated row lands.
  2. Skip the case verification → a call for another case is accepted.
  3. Skip the option check → an out-of-set answer is recorded.
  4. Ignore fail_policy → an outage is treated as a pass.
  5. Let the executor call laya itself → two requests per gate.
