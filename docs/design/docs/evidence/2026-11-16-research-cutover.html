Why the existing namespaces, not a new research namespace. default-restrict is a hand-written per-namespace policy in the shared clusters/strato/policies/network/baseline-networkpolicies.yaml; a new namespace would need its own entry there, plus its own egress rule, PSA and ambient labels. The adopted database needed one explicit step

apps/research/migrations/0001_media_baseline.sql is a pg_dump --schema-only of the reference's own database. sqlx would have re-run it against the schema it was dumped from and crashed (relation "collection_items" already exists, measured). Measured state before the fix: alembic_version = c7a1f4e9b820 — the exact revision the baseline was captured from — and no _sqlx_migrations table.

Resolution: a one-shot Job (media-baseline-seed) let the binary create the empty _sqlx_migrations table, then the baseline was seeded as applied:

version = 1, description = 'media baseline', success = true,
checksum = sha384(0001_media_baseline.sql) = 4d10d854…559551b0d24cc6898c053a796f2311cc29101

Re-running the binary then booted cleanly: media-discovery 0.1.0 on 0.0.0.0:8809. The row is created by sqlx's own DDL, not by hand, so the shape cannot drift from the library's expectations.

The media gate (2026-11-17, #226)

The reference's gate was three behaviours, each now ported and pinned by a test:

Credential Reference This service
none 401 AUTHENTICATION_REQUIRED 401, same code, WWW-Authenticate: Bearer
X-Tenant-Id: Bearer <licence> the licence's tenant introspected at LICENSE_INTROSPECT_URL; inactive/unknown/tenant-less → 401
bare X-Tenant-Id + Authorization: Bearer <service licence> the NAMED tenant, only for an allowlisted subject same; empty allowlist → every bare tenant refused (fail-closed)
bare X-Tenant-Id alone 401 — a claim is not a credential 401
a non-uuid tenant 400 INVALID_TENANT_ID 400, same code

Deviations, deliberate: no introspection cache (the reference caches 5 min; this service has had zero callers and a fresh check never serves a revoked licence from cache) and no trusted-CIDR branch (the vouch is required for every caller — strictly stricter than the reference's peer allowance).

Sequence, recorded honestly: the Python service was retired before the gate was restored, so on 2026-11-17 the Deployment was first withdrawn to 0 replicas (gitops#5318 — measured zero callers: a cluster-wide workload sweep matched only the Deployment itself, and the parent kustomization already recorded "zero callers in 7d"), then returned behind the restored gate. The live verification of the three shapes and the pinned digest are recorded on conveyor#226.
