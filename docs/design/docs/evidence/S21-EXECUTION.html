S21 step 11 — the level closes: apply-on-accept, prompt receipts and the recipe budget

Issue #697 · branch issue/697-s21-execution-loop · ADR 0019-accepted-draft-and-prompt-receipts · CONTRACT §29 · S21 §23 · resolves rework v1-p77-1, v1-p77-2

State: built. Measured at 54c51a63 on 2026-11-24, before the PR. The merge is the lane's last CI run; nothing here is claimed for main yet.

What changes at this level

Before: an L1-accepted draft was never applied — the executor finished the run succeeded and left the document unattached, so the gate's pass changed no card. An internal_agent could be created and activated with no prompt_ref; readiness skipped the check and agent.run called a model with no compiled text and a NULL prompt_sha256. The recipe-level budget_chars had a reader and a measured refusal but no writer.

After: the effective gate.precheck policy may declare meta.on_accept = "apply" (park is the default), and an accepted decision applies the draft through the one apply_draft_tx gate in the executor's finish transaction. An active internal_agent must resolve a prompt at creation, activation, readiness and execution, and every recorded call carries a 64-hex prompt_sha256. prompt_recipes.create writes the recipe's budget_chars, so the measured refusal is reachable from an authored recipe.
