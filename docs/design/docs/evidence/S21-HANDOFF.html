S21 step 9 — the work package's handoff: assign, remember, start

Issue: #649 · Branch: issue/649-s21-handoff · Date: 2026-11-24 · Baseline: origin/main@a8f67c3e (the #648 registry refresh)

What was built

  • cards.assign — one action, one transaction: it sets the card's active, tenant-scoped job binding, records what the receiver must know as one hot work_package_memory row, and starts the card's bound run through the same path runs.create uses (the andon, the binding's pin, the attempt, the run.execute enqueue and run.created).
  • The handoff is a write to an existing card, so it presents the card's version (If-Match or _version) like cards.update/cards.move: a card that moved underneath the caller is 412 with the current representation, and two concurrent handoffs produce exactly one run.
  • One live root run per card (SPEC_V2 §6.6.5): a card with a live run refuses 409 card_has_live_run naming it, before any write; uq_run_live is the race backstop.
  • One run-creation path: runs.create's body is factored into control/run_create.rs::create_bound_run_tx and both actions call it; runs.create's behaviour and tests are unchanged.
  • One memory writer: memory.remember's body is extracted as remember_tx and the handoff calls it; the note is an ordinary hot row the next run's Memory section selects.
  • No migration; no new scope; no new event kind (card.updated, memory.recorded, run.created).

Found in flight

The first cut passed the freshly read current.card.version to update_card_tx instead of the version parsed from the request's precondition. It compiled and every test passed except the new a_stale_card_is_refused, which caught a stale If-Match being silently accepted (a lost-update window). The handler now passes the precondition's version to the one writer, and the concurrent test's loser is a deterministic 412.

Not this step

Auto-start on a bare cards.move or a claim; a claim/renew/release verb; automatic apply of an L1-accepted draft; any budget mechanism (the #526 lane's); a handoff of a project-level (card-less) run; parent-run memory; a typed inputs/acceptance-criteria authoring surface on the handoff; a UI; PDDL storage; a second memory writer; the live model/laya proof; v1-p66-1's lane-refusal clause. cards.update's job_binding_id remains a plain edit and is not live-run guarded (ADR 0017 decision 7).
