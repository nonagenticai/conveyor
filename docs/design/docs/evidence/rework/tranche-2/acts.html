The manifest verdicts are only as good as the snapshot

The S03/T2 verdicts in docs/evidence/rework/{S03,T2}.json were taken by the branch verifier against a snapshot built by the DEPLOYED engine. That projection is older than the branch's: it omits architecture_contract.requested_by, omits document.published_at, and returned no demo-credit rows. Three of the reported failures (contract, review, demo credit) are therefore snapshot artefacts, not defects in the live record; the live contract, review and credit all satisfy their properties. The real gaps are S03's unrun closure and T2's non_conformant review level. The branch's snapshot does select the three fields but cannot be built against the live 0061 schema, so this tranche's acceptance evidence is reproducible only after the lane's migrations are applied.

The tranche review document records both corrections and was republished to v3.

What the pause cost, found by using it

S03's record is complete and its Phase-G review is compliant, so it should close. It cannot: projects.close requires the project's tranche to be authorised, in_review or closed, and tranche 2 is paused. There is no resume action, and a tranche can be reviewed only once. The pause this batch recorded honestly, because the exit criteria were not met, is therefore a one-way door that freezes the projects it was meant to gate. Recorded as v1-tr2-1 (P1, owner T1) with the three evidence lines; it is a product gap, not a data problem, and no SQL was used to work around it.
