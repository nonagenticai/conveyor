What had to be true to get there — measured, not assumed

  • Reachability. All four hosts were up the whole time; the 2026-11-25 note "unreachable" was the ssh invocation, not an outage. id_ed25519_mini and id_ed25519_mini2 are passphrase-protected and -o UseKeychain=yes is what unseals them. The tailnet ACL admits only :22 from m4, so every service was reached through a tunnel.
  • Spend budget. A spend-class tool is refused 429 unless the run declares limits.cost_budget_usd. A plain run has no job binding, so the run's inputs are written by the operator (the agent runtime is the production writer); the write and the read-back are in 2026-11-26/11b-budget-*.json.
  • Coding contract drift. The coding service requires an Idempotency-Key on the call (the broker claims it) and its current create body is input.source = {kind:"inline", files:[{path,text}]}; the older files map is a 422.
  • Retrieval's schema. retrieval.query had an empty input schema, so the published tool could only send {}; it now declares a closed {query, top_k} body.
  • Credentials. The tenant's sealed licence.token is admitted by the TTS gate (its W2V_LICENSE_GATE_TOKEN_APP_KEYS is speech), by ASR (its entitlement gate is dormant, so any active licence is admitted) and by scientific (introspection only). strata_rag accepts only app strata-rag. The licences bundle-token mint was refused 403 Role required: bundle-token-minter — a Keycloak realm role the conveyor's secure-apps client does not hold (the #776 gap). The owner chose the strata-rag service token instead: the *:<token> entry of STRATA_API_TOKENS, sealed as strata.token and never printed; the binding sends it as the Authorization bearer with the bare X-Tenant-Id. The refusal is kept at 2026-11-26/03-mint-strata.err.
  • Object storage. Speech, transcription and image_gen store documents; the local engine used the deployment's MinIO bucket (conveyor-documents) through an storage-1 tunnel, with the S3 keys read from the deployment's SOPS secret.

2026-11-25 measurement (history)

The first run of the gate found the code defects below and classified four calls as blocked: speech/transcription 503 (the staging copy carried no sealed licence.token), scientific 401 (the action sent no licence header), image_gen 503 (no object storage in the local engine). Those classes were real; the estate was not down. The 2026-11-26 execution above resolves them.

Product defects the live gate found

  1. The outbound Idempotency-Key was never forwarded (2026-11-25). The coding service refuses a create without it; the engine claimed the key for its own dedupe and sent nothing. The external dispatcher now forwards the caller's key, and the admin CLI can carry one.
  2. scientific was not publishable (2026-11-25). Its manifest status was draft while the gate named its probe; it is published.
  3. retrieval.query could not carry a query (2026-11-26). The action's input was empty while strata_rag requires query; the schema now declares {query, top_k}.
  4. The scientific and retrieval actions sent no credential (2026-11-26). Their toolkits now declare the sealed-profile adapter and their bindings carry the tenant secret, so the dispatcher sends Authorization: Bearer <secret> with the bare X-Tenant-Id.

Open, not gate-blocking

  • Retrieval returns zero hits for this tenant: it has no indexed leaves. The call reached the service and was ledgered; an empty corpus is not a failed call.
  • Issue 561 (research and Lean toolkits, first wave) remains open; webscraper and lean4 are draft and outside the published-toolkit clause.
  • T14 stays active by its acceptance manifest; closure is not part of this gate.
