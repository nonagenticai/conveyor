S06d — Interaction connector standard — web, Telegram, MCP first

Outcome

Web, Telegram and MCP are three instances of one class of user-interaction app. This slice builds the standard that makes the next connector cheap: one registry entry per kind (typed config + schemars schema, named secrets, default grant set, authenticate/parse/send), one inbound route and one command grammar, one multicast dispatcher with a first-response close, and a tenant-admin grant matrix.

Boundary

PieceWhereContract
Connector kindcrates/actions/src/channel/connectors/A ConnectorSpec per kind: config_schema (the web form), secret_fields (names of sealed secrets), default_actions, capabilities, and three functions — authenticate, parse, send. The webhook kind is the zero-Rust on-ramp for a JSON gateway.
Bindingchannel_binding(tenant, kind, route_key); config holds non-secret values and secret names. channels.bind validates the config with the kind's own schema and refuses a name the tenant does not hold.
