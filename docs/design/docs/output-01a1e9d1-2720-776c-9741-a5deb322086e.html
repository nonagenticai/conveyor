Artefact standard — P0 (retrospective, 2026-11-26)

Common metadata

The standard published on 2026-11-18 at 08:17:41 (01a1e9d1-2720-776c-9741-a5deb322086e) requires every architecture artefact to carry owner, reviewer and review date, version, purpose, stakeholders and scope, the related project, and its published document or contract. Every artefact also carries at least one link to what it derives from, realises or reuses. That metadata is what makes an artefact a typed record rather than prose.

Catalogues

A catalogue records a typed list, such as a driver, goal and objective catalogue, a requirements catalogue, a data entity catalogue or a technology standards catalogue. The standard fixes the type and the required fields so a catalogue can be queried and re-used rather than read as narrative. The definition set contains four catalogue artefacts of that shape.

Matrices

A matrix records relationships between two typed sets, such as the stakeholder map 01a20234-1244-74cd-b0e2-1ef1d8e04021, which the brief records as a matrix in Phase A. The standard requires the matrix's axes and the artefact metadata to be explicit, so the relationship is inspectable. The standard distinguishes a matrix from a link: a matrix records a relationship between typed sets, while a link records derivation, realisation or reuse.

Diagrams

A diagram is a document with typed metadata and a viewpoint, not a live metamodel; SPEC_V2 §8.6 rules out an ArchiMate modelling tool. The solution concept 01a20231-c661-79d8-9871-23b10eb3a2bb and the business capability map 01a2023a-5a2e-799d-8189-37edc4991b8c are the definition set's diagram artefacts. The standard requires the same metadata and links on a diagram as on a catalogue or matrix.

Links

Links are the trace edges: each artefact records what it derives from, realises or reuses, and architecture-governed work requires the link at creation time under SPEC_V2 §8.5. A link is not decoration; it is how the governance screen answers which requirement a run proves and where the evidence sits. The standard requires at least one such link on every artefact in the pack.

Repository

The artefact standard was adopted with its repository and type catalogue as part of the architecture capability baseline. In P0 the repository is the console's document store and the design site, with each artefact published as a document under the project. The typed repository rows behind the standard are T9's (#81), so P0 claims the published standard and its adoption, not the typed store.
