Project Context Diagram — P0 (retrospective, 2026-11-26)

Context

The work package is P0's retrospective rework: the programme-definition project of the conveyor buildout. Its boundary is the programme record — projects, artefacts, documents, registers, baselines, contracts, approvals and the benefit profiles — plus the public design pack the site serves. Delivery projects and their own records sit outside the boundary; they consume this definition set rather than belong to it.

Affected organisation

The sponsoring group authorises the mandate and the tranche decisions. The SRO is accountable for the coherent capability and the benefits, the BCM owns each benefit and its transition, and the programme board is the SRO's decision forum. The programme architect authors the definition set under delegation 01a1ff1f-e4ba-72dc-9c1a-13049933cf14; the programme office consumes the closure record.

Affected systems

The operating record (PostgreSQL 18, migration 107 on this lane) holds the project, artefact, document, register, baseline and contract rows this project writes. The public design pack is generated from a snapshot of that record. The document store at MinIO is unreachable from this box, so the replay base keeps published bodies in the database; the output-standard template governs every body's headings.
