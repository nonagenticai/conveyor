Closure review — T0 Model and contracts (retrospective, 2026-11-21)

Outcome vs acceptance

The SPEC_V2 §12 T0 gate has six clauses. Each is met:

  • A job is created in the conveyor. job_catalogue is the position; the organisation action family serves job_catalogue.create|update|retire|get|list over HTTP and MCP from one ActionSpec.
  • A release is published, and a binding pins its hash. job_releases.publish writes an append-only job_release whose release_hash is SHA-256 over the canonical snapshot; job_bindings.create stores the hash and the frozen snapshot. crates/store/tests/organisation.rs::release_hash_is_deterministic_and_publish_is_idempotent proves the same job and pins hash identically and that unchanged content is one release.
  • A run on a retired binding refuses 409 job_binding_stale. The binding is resolved before the run INSERT and the refusal names both hashes: crates/store/tests/organisation.rs::a_run_pins_its_binding_and_a_retired_or_mismatched_pin_is_refused; the action surface is exercised in crates/actions/tests/sop_ingestion.rs::a_bound_job_runs_the_pddl_steps.
  • No concept has two stores. SPEC_V2 §10.1 assigns each fact one system of record; job_catalogue is the position and V1's job remains the durable work queue, two concepts, neither renamed into the other; no manifest is imported.
  • A test-only third executor kind registers without editing the run path. executor_kind is an open slug; crates/domain/src/executor.rs::a_third_kind_registers_without_touching_the_builtins and crates/store/tests/organisation.rs::third_executor_kind_registers_without_editing_the_run_path prove it.
  • The decision-ladder types exist. decision, decision_option, decision_policy, decision_policy_refinement and laya_inference_config are created with FORCE RLS; T2 owns evaluation, so no evaluation path is claimed here.
