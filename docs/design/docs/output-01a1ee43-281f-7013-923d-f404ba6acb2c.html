Current state

T16 targets one pipeline: store a tenant document as an untrusted source, convert it into relational procedural knowledge and a draft executable procedure, and publish both behind a gate. Execution is built; ingestion and ontology are not.

  • Executable ordered process — built. process/process_step (renamed from procedure* by 0035) hold agent | computed | gate | call steps (crates/domain/src/process.rs:StepKind), authored by processes.create (crates/actions/src/process/processes.rs:processes_create). A step has an action, input template and outputs but no preconditions or effects (crates/actions/src/process/views.rs:StepIn).
  • SOP-as-judge — built. procedure is now the SOP a step is judged against (migrations/0035_process_tree.sql:procedure), validated at publish (crates/domain/src/procedure.rs:validate_publish), and owns the procedures.* family (crates/actions/src/procedure/procedures.rs:procedures_publish). Not executable.
  • Process map — built (migrations/0035_process_tree.sql:process_map, crates/actions/src/process_map/maps.rs:process_maps_create); declarative, never the executor.
  • SOP source — partial. governed_asset accepts sop_source (migrations/0044_plan_spine.sql:governed_asset; crates/domain/src/governance.rs:AssetKind) but no action writes that kind (crates/actions/src/governance/assets.rs).
  • Document ingestion — built. documents.ingest hands one document to the ingestion capability (crates/actions/src/documents/ingest.rs:documents_ingest); knowledge.query retrieves pinned leaves (crates/actions/src/knowledge/query.rs:knowledge_query).
  • Capability substrate — built (migrations/0020_capability.sql:capability); only list/get/bind_knowledge exist (crates/actions/src/capability/capabilities.rs:capabilities_bind_knowledge), so capabilities.design|publish are absent.
  • PKO — absent. No pko_* table exists; the newest migration is 0051 (migrations/0051_tranche_review.sql:programme_tranche_review). §10.3 specifies pko_release/pko_entity/pko_relation; #85 builds them.
  • RDF/OWL/Turtle and BPMN/Visio/draw.io conversion — absent. No parser or PDDL code exists; the existing ingest modules are document submission (crates/actions/src/documents/ingest.rs) and OpenAPI action ingest (crates/actions/src/ingest.rs:DiscoveredAction) — neither converts a process document.
  • Tool platform — absent. No tool* table or tools.* action exists; T13 (#76) is status:claimed, open and unmerged (§11.8), and live conversion is blocked at that seam.
  • Ladder and approvals — built (migrations/0046_decision_ladder.sql:decision, migrations/0050_approval_policies.sql:approval_policy).

Published processes are immutable. A binding may name any process row — crates/actions/src/organisation.rs:job_bindings_create checks existence only — and the published version is resolved at run start (crates/actions/src/process/runs.rs:resolve_version). "An unreviewed source never binds" has no carrier yet: no artefact records its source.

Build vs reuse

  • PKO storage — build, reuse nothing. Relational rows per D53; no triple store, reasoner or SPARQL. RDF/OWL/Turtle are import-only: the converter emits complete rows before publish and no runtime query extends them.
  • Executable draft — reuse process/process_step. Add PDDL columns; do not create a second procedure aggregate (P1, P10). Publication stays processes.publish.
  • SOP intake — reuse governed_asset(kind='sop_source') and documents.ingest. Build one writer and the approval path; no new asset table.
  • Structural formats — build the mapping, reuse a parser crate. RDF/OWL and BPMN mappings are deterministic; parser licences are reviewed.
  • Prose SOP conversion — build a generation step. L2 in the ladder, not a decision; a human gate publishes. No reuse candidate exists.
  • Backends — reuse the T13 broker only. T16 declares toolkit needs and writes no HTTP client (§11.3); live conversion waits for T13.
  • Knowledge packs — reuse strata_rag through capabilities.bind_knowledge. Never host embeddings.

Risks

  • Name collision on procedures.*. §10.4 lists procedures.ingest_sop|…|publish, but procedures.publish already publishes the SOP judge. Check: git show origin/main:docs/design/data/actions.json | grep '"procedures\.' returns six names; a duplicate is refused (crates/actions/src/ingest.rs documents action-name-conflict).
  • Spec prose versus schema drift. §10.3 says procedure/procedure_step gain PDDL; the executable tables are process/process_step. Check: git grep -n 'RENAME TO process' origin/main -- migrations.
  • Unvalidated PDDL. A publish with an unsatisfiable precondition breaks a run. Check: (to create at #85) a publish-refusal test with a malformed precondition.
  • Untrusted SOP as instruction. SOP text reaching a prompt path is the injection surface. Check: (to create at #85) a fixture ordering the converter to publish; output must be draft rows.
  • Absent tool seam. A direct backend call violates §11.3. Check: git grep -n 'CREATE TABLE tool' origin/main -- migrations returns nothing.
  • Speculative aggregates (P10). Three PKO tables with no consumer are dead weight. Check: each is read by the bound-run path and by one metric.
  • Edit rewrites history. An in-place edit of a published PKO entity changes what a published procedure was validated against. Check: (to create at #85) an update on a published release is refused.

Open questions

  1. Does the procedure land as a process draft, or as an intermediate artefact producing one?
  2. Which PDDL fragment: STRIPS with typing, or an ADL subset, and who owns the grammar?
  3. Is the SOP judge one row per derived process, or a shared tenant library row?
  4. Do intake verbs stay in procedures.*, or move to a new family?
  5. One card per document or per batch; how much Visio export is BPMN-equivalent?
