Kata — the benefit row lifecycle: no update or delete action

Context

The MSP benefit store has benefits.create|get|link|list and no update or delete. Two consequences are live in P0's definition set:

  • The B1 row carries the four fields the completeness rule requires (baseline, target, method, owner) but not the path levels (objectives, capabilities, observable outcome, project). It was created before those levels were supplied, and there is no action to correct it. The benefits map and the B1 profile disclose this and carry the path themselves.
  • Two probe rows remain from schema probing: B-PROBE (benefit) and tranches 98/99. They are disclosed on issue #260; there is no action to retire them.

Decision

Add benefits.update (If-Match, admin/portfolio:write) with the same completeness rule, and a benefits.delete (or a documented retire) that refuses a benefit referenced by a live link. Retire the probe rows and correct B1's levels through the new action. Until then, the documents name the gap rather than hiding it, and no number is invented to fill it.

Consequences

A programme reader sees B1's path in the profile but not in the row; the map's row gaps section says so. The probe rows appear in benefits.list and tranches.list and are excluded by intent, not by a filter the reader can see. The correction is a small action unit, not a data edit by SQL.

Evidence

  • benefits.list on programme 01a1d039-0d24-7d16-ae52-4841e96ccfac: B1 row 01a1e9de-4e4f-757e-a8c8-bf3522e5adcf; B-PROBE 01a1e9dd-9759-7095-97eb-0c4b8f1e4988.
  • The benefits map (01a1e9e0-750d-71b9-8230-177eebe80e95) and B1 profile (01a1e9e0-1b2e-7353-9361-16a81a99d354) carry the disclosure.
  • Issue #260 records the probe rows for cleanup.
