Project Brief — S04 Action registry

Outcome

One action declaration serves HTTP, MCP, OpenAPI, the admin CLI and external ingest: 549 actions from a single registry, 580 served operations locked by hash.

Boundary

Out of scope: the screens (S12), the board (S05) and the tool platform (T13). The registry must not fork per transport; a second declaration path is a defect.

Reuse sources

  • crates/actions/src/lib.rs and crates/actions-derive — the ActionSpec declaration and macro.
  • crates/actions/src/invoke.rs — the one invocation path with idempotency and audit.
  • crates/api/src/actions.rs — the HTTP route over the same registry.
  • crates/actions/src/lock.rs — the served-spec lock.

Inception units

The gate analysis (derive, manifest, OpenAPI, MCP, invocation, ingest), the transport-parity choice, and the lock's hash discipline are the inception units.

Dependencies

S02 (the skeleton) and S03 (the domain schema); tranche 3; issue #3.

Acceptance

acceptance/programme/S04.toml is the gate: the derive crate, the registry and the vocabularies, the parity test, the lock check and the ingest round-trip.

Capabilities

One declaration per action; one invocation path; one served spec; one external-ingest fold.

Plan

Two deliverables — the ActionSpec derive crate and the registry and spec vocabularies — accepted under change 01a2054b-3f86-7959-b2ad-f1edc5b0bb55, credited at the tranche-3 demo, and closed against the frozen baseline 01a20256-44d0-731d-b345-fffc5f3ac9e8.
