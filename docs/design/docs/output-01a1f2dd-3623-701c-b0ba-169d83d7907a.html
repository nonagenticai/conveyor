Entries

Ten entries, identifiers P1–P10. Each is a row: axis_a is the id, axis_b the item name, and the value carries statement, rationale, implications and evidence. Statements are recorded to their rule and the supporting fields condensed; the published document carries the full wording.

P1 — One model, one store, one action registry Statement: A programme's work, decisions and evidence are rows in one Postgres database written through one action registry; one table and one action set per concept. Rationale: Fragments of one model are the estate's pain; one registry makes permission, audit and replay uniform. Implications: A new capability is a table plus actions in this workspace, not a new service; no feature keeps a private file or cache as its record of truth. Evidence: crates/actions/src/lib.rs; migrations/*.sql; crates/actions/tests/registry.rs

P2 — Every mutation is an action; the database is not the API Statement: A write goes through an action with its scope, tenant, precondition and event; no handler, UI or script writes rows by SQL. Rationale: The action envelope carries RFC 9457 errors, preconditions, revision history and audit. Implications: A new write is an action with a schema, a scope and a test; a read-only probe is BEGIN READ ONLY. Evidence: crates/actions/src/invoke.rs; the registry test committed_action_dump_matches_the_registry

P3 — Tenant isolation is structural, not a filter Statement: Every tenant-owned table has RLS enabled and forced, and every query runs under the tenant's scope; a cross-tenant id resolves to 404. Rationale: begin_scoped is the only path that sets the tenant GUC; a filtered query is one forgotten predicate from a leak. Implications: A new table ships with its policy and a foreign-tenant 404 test; no session-level GUC through a pooler. Evidence: crates/store/src/scope.rs; the registry test a_foreign_tenant_parent_id_resolves_to_404_never_to_a_write

P4 — Publication is a decision, never a side effect Statement: A row is public only when an admin's publish decision makes it public; author markup is never executable on the public page. Rationale: The executor never approves its own work; documents.publish is the only action that moves the public bit. Implications: A new public surface filters on the public bit and carries the tenant; preview uses the same renderer as the public page. Evidence: crates/actions/src/documents/revisions.rs; crates/render/src/markdown.rs

P5 — Every output is versioned, attributable and reversible Statement: A text output carries its author, a content hash and a revision history; every edit is versioned and a restore copies a version forward. Rationale: An output a reviewer cannot trace to author, version and evidence is not auditable. Implications: A work-product aggregate reuses the document model or carries the same provenance; deletion is a tombstone. Evidence: migrations/0042_document_workflow.sql; crates/store/src/document.rs

P6 — Programme truth is computed, never hand-written Statement: A project's status, units, dependencies and expected outputs come from measured sources and are regenerated by scripts. Rationale: A hand-written status is the first thing to rot. Implications: A new programme fact gets a generator and a --check gate; a document may explain the truth but may not be its only home. Evidence: scripts/build-coverage.py; scripts/build-programme-seed.py; scripts/check-output-standard.py

P7 — Gates refuse; a gate that never refuses is broken Statement: A gate is a refusal with an actionable reason, exercised by a test that proves the refusal. Rationale: The programme's publish and dependency gates exist because a publish without evidence happened; a refusal is the product, not an error path. Implications: A gate names what is missing and the refusal is covered at the caller's boundary. Evidence: crates/actions/tests/authoring_standard.rs; the 409 blocked_by gate in crates/actions/src/programme.rs

P8 — Typed dependencies, explicit gates Statement: A dependency between projects is typed and the programme gate enforces the blocking kind. Rationale: Untyped coupling hides the order the programme actually needs. Implications: A project's inception names its dependencies and the contract it sits under. Evidence: migrations/0044_plan_spine.sql; crates/actions/tests/plan_spine.rs

P9 — Secrets never leave their boundary Statement: A secret is write-only; no action returns its value, and no secret or private host enters a public output. Rationale: The repository is public, so a leak is permanent. Implications: A credential is referenced, never printed; public outputs are scanned before publication. Evidence: crates/actions/src/documents/secrets.rs; scripts/ci/no-private-refs.sh

P10 — The estate is one deployable service per concept, absorbed not duplicated Statement: A service the organisation depends on is this workspace's code or an absorbed, contract-tested module behind an action; a second deployment of the same concept is retired. Rationale: ADR 0005 fixes the absorption sequence. Implications: A new integration adds an action and a client in this workspace; a retired service's data is migrated, not forked. Evidence: docs/decisions/0005-absorption-sequence-and-repo-scope.md; crates/actions/src/ops/
