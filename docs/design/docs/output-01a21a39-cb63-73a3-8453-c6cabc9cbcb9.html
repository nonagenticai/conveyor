Project brief — S06 Control Plane (retrospective, 2026-11-27)

Outcome

S06 turns claims, runs, approvals, andon, comms and notifications into one durable control plane: one conditional UPDATE per claim with a monotonic claim_fence, one idempotent job row per period in place of fr's 14 timers, one approvals.decide path with required_decisions and decided_by_kind shared by web and Telegram, an andon_state singleton that pauses the poller and refuses runs.create, and one message plus N delivery rows per notification with a bounded retry. The record claims the slice built (meta.measured_status: built); the acceptance gate is not evidenced at the snapshot, and this rework records that rather than claiming a pass.

Boundary

Out of scope: the signed mcp_server channel (S06a: HMAC, payloads, ±300 s), MCP tool surfacing (S10), project_request.timeout (S07), the UI (S12 screens only) and the audience screens (PENDING-S0). S06 must not fork a second claim path, a second approval decision path, a second event write path or a second delivery store; the plan's traps fix those refusals, and the signed transport stays S06a's.
