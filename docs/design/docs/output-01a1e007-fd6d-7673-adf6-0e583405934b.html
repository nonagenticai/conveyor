S21 — Message construction (the compiled prompt)

Track: v1 · Tranche: 9 · Measured status: partial · Plan: docs/plans/slices/S21-message-construction.md Dependencies: S11, S13, S15, S16 · Issues: #15

Outcome

A prompt is compiled at run time from the procedure and the other system, tenant and project sources, stored in Postgres, with the compiled text's SHA-256 as its provenance key.

Boundary

In scope: the recipe (prompt/prompt_section), the pure compile pipeline, provenance and the PDDL evaluation. Out of scope: authored prompt templates; the V1 seam is built and is not re-opened.

Reuse sources

V1's prompt and prompt_section tables (migrations/0030_prompt_catalogue.sql) and conveyor_domain::prompt::compile over PromptFacts; the sources in crates/.

Inception units

  1. analysis — current state and reuse: inventory what already exists, the contract and licence constraints, the build-vs-reuse decision, and the risks.
  2. architecture — the project's design: aggregates, tables, actions, modules, integrations, the decision record, and acceptance.

Both are documents on this project with meta.category set to analysis / architecture; both published is the inception standard.

Dependencies

Blocked-by: S11, S13, S15, S16.

Acceptance

  • A step whose recipe requires procedure and whose run has none fails by name, before a model call.
  • The same recipe and the same facts compile byte-identically (hash equality is the test).
  • Changing the card changes the hash; changing an unrelated tenant's card does not.
  • An over-budget section refuses with the measured size, never truncates.
  • The prompt audit can name the compiled text it audited by (prompt_ref, prompt_sha256).

Verify: the gate above is the acceptance evidence
