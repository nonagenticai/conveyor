crates/actions/src/coach.rs:coach_interrupt refuses a run that did not fail (coach.run_not_failed), a card that is already a coach card (coach.about_a_coach), and a card past the cap (coach.chain_capped). It renders the signature from error class, process key and failing step position, closes an expired window with store::coach::close_expired_tx, and then either escalates an open same-signature interruption through ESCALATION_GATE with store::coach::mark_escalated_tx, or creates the coach card through cards.create (type coach, from crates/store/src/coach.rs:COACH_CARD_TYPE) and starts the coach run.

crates/actions/src/coach.rs:coach_triage refuses a class outside crates/store/src/coach.rs:TRIAGE_CLASSES, a confidence outside 0..=1, and a blank narrative; a second triage is coach.already_triaged. :coach_remedy refuses a class outside :REMEDY_CLASSES and a triage below the confidence floor unless the remedy is ask (coach.low_confidence); a second remedy is coach.already_remedied. ask opens the ASK_GATE approval on the interrupted card; a class in the policy's systemic set starts exactly one kata.open run and records it with store::coach::set_kata_candidate_tx. :coach_escalate refuses an already-escalated interruption (coach.already_escalated) and emits coach.escalated.

Gap

  • The design's class→remedy matrix is not enforced. Architecture artefact T4-AM-01 fixes 5×6 cells as default/allowed/refused; the delivered crates/actions/src/coach.rs:coach_remedy validates only closed-set membership and the confidence floor, then accepts the caller's remedy_class (with a class-derived default when none is supplied). No refused cell exists in code: git grep -n 'refused\|allowed' origin/main -- crates/actions/src/coach.rs crates/store/src/coach.rs returns doc comments only. The §12 gate does not name the matrix, so this does not fail the gate; it is an unbuilt design detail.
  • No concurrency test. The design's acceptance #6 (coach_concurrent_signature) has no counterpart in crates/actions/tests/coach.rs. Per-signature uniqueness is enforced by uq_coach_interruption_open and asserted sequentially, not by a racing pair; the index is real, the race is unproven.
  • Design and delivery diverge on names and placement. The design named migration 0052_t4_coach.sql, a status column, card type coach_interruption, and a child card in the interrupted card's waiting lane; delivery is migrations/0057_coach.sql, state + closed_at, type coach, and a card created in the interrupted card's own lane with parent_card_id: None (crates/actions/src/coach.rs:coach_interrupt). The migration records this as decision Q1 — a deliberate change, still a divergence from the design document.
  • The seed records disagree about the agent's scope. The v2 process allowed_actions exclude coach.remedy (seed/processes/named.yaml, cap.kanban_coach.handle_error.v2), while seed/organisation.json (kanban_coach.definition.grants) still lists coach.remedy. The process list is the runtime gate; the two records disagree.
  • Coach-card exclusion from flow and WIP reads is not verified here. D-T4-3 relies on that exclusion to keep the board readable; this review verified the card type and the uniqueness, not a flow/WIP read predicate.
  • The kata handoff is a run, not a kata. coach.remedy starts kata.open; the six Gets are T5. "A systemic class opens a kata" is true at the handoff boundary and says nothing about kata execution.
