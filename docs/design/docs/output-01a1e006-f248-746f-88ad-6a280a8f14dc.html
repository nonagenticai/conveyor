Governance and organisation

Programme: conveyor buildout · Status: adopted by P0 · Date: 2026-11-15

1. Roles

RoleWhoAuthority
OwnerGeorgeRulings, licensing, the merge of a lane's PR, credentials, anything irreversible on shared state
MaintainerThe owner, and a maintainer team when it existsReview, merge, release; never changes a gate it is judged by
Session (Claude)The working sessionDiagnoses, implements, validates, opens one PR per unit; never merges the owner's PRs, never changes its own gates
ContributorAnyone, including the publicOpens an issue or a design PR; claims a ready unit with the four-check protocol; signs the DCO

The conveyor's own organisation is the model it implements: industry → department → job, immutable releases and tenant-scoped bindings (docs/SPEC_V2.md §4). The roles above are the programme's operating positions until the conveyor's jobs can carry them.

2. Decision ladder

Every decision is one of: a rule, a laya choice, a generated draft, or a human decision. The rows are the same shape and pin the policy, refinement and configuration versions that produced them (docs/SPEC_V2.md §7). The programme adds three rules:

  • Owner rulings override the plan. Where this document conflicts with an owner ruling, the ruling wins, and the plan is corrected in the same PR.
  • A gate that cannot refuse is a defect. Every gate ships with a negative test; a never-refused gate is flagged, not celebrated (docs/SPEC_V2.md §14, R5).
  • A decision record is a document on the project when it is programme-level; an ADR under docs/decisions/ when it changes the code's architecture. The two are linked, not duplicated.

3. Assurance

  • Evidence over claims. DONE means the deliverable is observed landed: the test output, the live probe, the merged commit, the deployed revision (docs/plans/03-DELIVERY.md).
  • Independent validation. A builder does not validate its own unit; a fresh validator checks the artifact before a push, merge or handoff.
  • The measured programme. A project's status is computed from slice frontmatter, migrations, the action-registry dump and the pack (scripts/build-coverage.py); a hand-written status is not a status. The Validation page is the public rendering of that instrument.
  • The public gates. no-private-refs, the secret scan, DCO and the eight design-pack checks run on every PR; the local gate runs before the PR exists.

4. The unit protocol

  1. Claim. An issue with the unit label and a state label. The four checks: the issue is not blocked; no live branch or open PR covers it; the plan path resolves; the acceptance is executable. Push the branch when the work starts; an unpushed branch claims nothing.
  2. Branch. One issue, one branch issue/<n>-<slug>, one PR (Closes #<n>). A slice is a commit on that branch, never its own PR.
  3. Work. The local gate first: format, lint, tests, the pack checks, build-docs --check, the coverage check. A red gate stops the PR.
  4. PR. Non-draft, when the unit is complete and the local gate is green. The PR body carries the measured evidence and Closes #<n>.
  5. Merge. The owner merges on green. The merge is the second and last CI run for the unit; the deployment is verified against the merge revision, not against a hopeful status.

The full contract is docs/plans/03-DELIVERY.md; the session entry contract is CLAUDE.md.

5. Public collaboration

  • Input is GitHub only. Bug and feature forms carry the privacy checkbox; a contributor claims a ready unit in a fork, signs the DCO, and opens a PR; the public CI gate runs the same checks.
  • Design changes are pull requests against programme/. A maintainer applies an accepted change to the database; the next export supersedes the file. The DB is the store; the mirror is the public record.
  • No in-app public accounts. The public site is read-only; the signed-in console is the operator's. A public comment, account or moderation queue is out of frame.

6. Data and infrastructure invariants

  • One service, one database, one database user; a service never uses another's credentials.
  • Secrets are per service; a rotation is a new value in the source of truth, never a live patch.
  • Tenant isolation is enforced in the action layer and by row-level policy; a foreign key never enforces tenancy.
  • The cluster is downstream of code: a broken workflow is fixed in the workflow or the archetype, never by widening the cluster to absorb it.

7. The andon cord

One stop stops every execution. Pulling it is a decision; releasing it is a decision with evidence. No session releases it on its own judgement, and the stop is recorded as an incident.

8. Amendment

This document is part of P0's definition set. An amendment is a new version of this document on P0, published, with the reason; a silent edit to a governance rule is a defect.
