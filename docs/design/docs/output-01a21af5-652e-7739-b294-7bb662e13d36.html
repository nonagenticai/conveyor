GEMBA-WALK — Architecture design (PSA and HLD)

Amendment 2026-11-27 (CR-WALK-001, ADR 0024). The client is served at https://game.nonagentic.ai/ at the root from the same image and service, with its own public client conveyor-game in the conveyor realm; the operator origin's /walk/* 308s to it. The host boundary, the azp allowlist and the live sign-in are added below (R17–R19, AD10, D1). The earlier /walk/ sub-site is retained only as the no-host dev/CI shape.

Context and boundary

GEMBA-WALK adds a second client, not a second system. It is a static client at https://game.nonagentic.ai/, served at the root from the same image and service as the API (so the API is same-origin), with its own router, sheets, world, identity client and Playwright suite. It adds no table, action, event, port, decision store or read model. Every read is a literal GET route where one exists, or the owning read action (programmes.list is one); every write is POST /api/actions/{name}/invocations with the standard envelope and headers; a capability the server does not expose is an honest gate.

The design covers the client architecture, the route/action parity model, the WorldView port, the seats-as-presets rule, the serving fallback and the parity instrument. apps/web remains the normative operator UI until the P6 gate. The design pack at /design/ is unchanged.

D1 — Technology view

Static HTML/JS/CSS sub-site served from the existing image and origin; no new port. The baseline world simulation is bevy_ecs 0.20.1 in crates/walk-world, compiled to wasm32 and loaded behind WorldView (ADR 0022); the renderer is the canvas-2D projection (ADR 0023), measured against WebGL2 in P0 (bundle, startup, frame time, WebGL requirements, CI build and DOM-overlay input); WebGL2 remains a candidate behind the port. Browser APIs: fetch, streams, Web Crypto (PKCE), sessionStorage (verifier only), history/URL. Build: GitHub-hosted preflight for the wasm compile (no local cargo); the walk's static assets are copied by the Dockerfile. Tests: Playwright against the dev server; node --test for pure modules. No SSR, no server runtime, no third-party hosted service.
