Context and boundary

T14 owns the import wave: which live services become toolkits, which contract each pins, which probe proves it, which binding grants it, and the zero-use and outage behaviour. It fits the blueprint — one workspace, one action registry, one Postgres, no new port (§10.6). T13 (#76, open, status:claimed) owns the four tables, broker, effect classes, credential profiles and storage adapter; T14 writes catalogue rows, probes and bindings over it. It must not duplicate the broker (§11.3), the tool_call ledger, the ops client, the captured locks or the coding fleet's code, nor own T15's authoring, T7's incidents or any rewrite (ADR 0007).

Aggregates, tables and actions

Rows. toolkit is the root at service@version; tool rows are its operations; tool_binding pins a version to a job binding or run; tool_call is the ledger. All four are planned under T13 (#76, §11.8); none exists in migrations/ at main@61edfcf8. T14 adds no table (P10); zero-use is a query.

Reused (built): migrations/0002_domain.sql:governed_asset, migrations/0013_documents.sql:secret, migrations/0001_platform.sql:event, :audit_event, migrations/0024_s16_inference_audit.sql:inference_call, migrations/0048_host_registry.sql:host_registry, migrations/0050_approval_policies.sql:approval_policy.

Invariants. I1 one toolkit per service identity — destination alias plus contract, never port (8812 carries two services). I2 published versions are immutable; a change supersedes. I3 publication needs a read-only probe and one recorded live call. I4 a draft is unbound; tools.call fails 409 tool_not_ready (P8). I5 a ceiling only narrows. I6 a failed probe unbinds new runs; in-flight finish (§11.9). I7 no caller-supplied URL; the alias is fixed. I8 no write tool without idempotency and read-back (§11.3).

Actions — existing, each resolves in docs/design/data/actions.json at main@61edfcf8: ops.pods, ops.deployments, ops.events, ops.logs, ops.ci_status, ops.flux_status, ops.scale, ops.host_status, ops.host_logs, artifacts.list, billing.summary, coding_jobs.create, coding_jobs.get, retrieval.query.

Actions — (to create): toolkits.import_openapi|publish|list, tools.list|get|probe|call|publish|retire, tool_bindings.create|update|retire, tool_calls.list — T13 (#76), §10.4/§11.8; tools.zero_use — (to create at #83), §11.9 and the T14 gate.

Events. tool.called (to create at T13) and tool.probe_failed (to create at #83), consumed by the binder to revoke new-run eligibility.

Decisions

D1 Import captured openapi.lock.json, not live introspection. Alternative: fetch /openapi.json at publish. Consequence: reproducible pins. The lock's pinned digest is compared with the probe's reported digest at publication; a mismatch is 409 tool_contract_stale (to create at T13, #76), and the standing probe reports the same drift after publication.

D2 Identity is the destination alias, not the port. Alternative: port-keyed names. Consequence: 8812's two services never collide.

D3 Probes are read tools published with the toolkit. Alternative: external monitoring. Consequence: one ledger and schema; a non-read probe is refused.

D4 No new tables. Alternative: a health or report table. Consequence: zero-use is computed from tool_call.

D5 Planned services enter as draft, unbound. Alternative: omit them. Consequence: visible pipeline, fail-closed; drafts never callable.

D6 Ops read tools share the client and declaration with ops.*. Alternative: bind tools to handlers, or omit ops. Consequence: P1 holds — one implementation, two surfaces — with a parity test.

D7 The scientific scale-up is an approved ops.scale call, separate from the probe. Alternative: the probe auto-scales. Consequence: destructive effect, approval and audit; the gate is a scripted evidence run, not CI.

D8 w2v and video-compiler pin the live contract and are superseded when apps/media replaces their stages (D58). Alternative: wait for the rewrite. Consequence: tools now; supersession is a versioned publish.

Acceptance

Gate, verbatim (§12 T14): "each published toolkit has a probe and one live call; scientific_processor is scaled up for its probe and one live call, then scaled back; a zero-use report exists; a backend outage unbinds new runs and in-flight runs finish".

  • A1 — a probe per published toolkit. Verify: scripts/prove-estate.sh probe-all (to create at #83) returns one green row per published toolkit, and crates/actions/tests/estate_toolkits.rs::every_published_toolkit_has_a_read_only_probe (to create at #83) refuses a probe declaring a write or spend effect.
  • A2 — one live call per published toolkit. Verify: scripts/prove-estate.sh call-all (to create at #83) plus crates/actions/tests/estate_toolkits.rs::every_published_toolkit_has_one_live_call (to create at #83); the resulting tool_calls rows are recorded on #83's evidence table.
  • A3 — scientific scale-up, probe, call, scale-back. Verify: scripts/prove-estate.sh probe scientific_processor and … call scientific_processor (to create at #83) around an approved ops.scale, then kubectl -n <namespace> get deploy scientific_processor -o jsonpath='{.spec.replicas}' → 0.
  • A4 — zero-use report. Verify: crates/actions/tests/estate_toolkits.rs::the_zero_use_report_flags_only_uncalled_tools (to create at #83) — an uncalled tool is listed, a called one is not.
  • A5 — outage unbinds new runs, in-flight finish. Verify: crates/actions/tests/estate_toolkits.rs::a_backend_outage_unbinds_new_runs_while_in_flight_finish (to create at #83) — the new run is refused 409; the in-flight run finishes succeeded or failed (its tool_call may record a backend error), never refused mid-flight.
  • A6 — a draft is never callable. Verify: crates/actions/tests/estate_toolkits.rs::a_draft_toolkit_is_unbound_and_uncallable (to create at #83) — 409, no tool_call written.

Architecture artefacts

PSA set at inception

Principles applied (SPEC_V2 §3). P1 one record per fact: toolkit rows are the only catalogue. P2 tool selection is not an LLM decision. P5 probe and live call before publication. P8 draft or unhealthy means 409. P10 no new table. P11 ceilings, aliases and approvals are tenant rows.

Requirements. R1 every live §11.2 service has a published toolkit. R2 every job call goes through tools.call (§11.3). R3 effect classes gate each operation (§11.4). R4 the four tables and actions exist (§11.8). R5 probes, health and zero-use follow §11.9. R6 drafts stay uncallable (§11.2, P8). R7 the §8.1 metadata is carried.

Stakeholder map. Platform owner; delivery and verification jobs; operations; the media tenant; the AHTAPol tenant; architecture and security review; the independent reviewer on #347.

Driver → goal → objective. Driver: today's ad-hoc externals are not tool-ledgered (no tool_call) and are unowned. Goal: one governed catalogue over the live estate. Objective: every published toolkit has a probe and one live call; the three draft groups (evidence_review, discovery and the planned AHTAPol services) exist and are uncallable; the zero-use report names every uncalled tool; an outage unbinds new runs while in-flight runs finish.

Solution concept. Contract capture → draft → probe → contract test → publish → bind → probe schedule → zero-use retirement; drafts stop at step two.
