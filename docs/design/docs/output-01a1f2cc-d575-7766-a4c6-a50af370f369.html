Gap

  • The catalogue actions are unbuilt. git grep -nE 'name: "(tools|toolkits|tool_bindings|tool_calls)\.' at f14b7d36 returns exactly one hit, crates/actions/src/tools.rs:57. tools.list/get/probe, toolkits.publish/retire, tool_bindings.* and tool_calls.* do not exist as actions; the ledger is readable only through crates/store/src/tool.rs::calls_for_run/::calls_for_tool. The test header (tool_platform.rs:7-9) calls this deliberate: "this slice ships no catalogue actions; the estate import is T14".
  • The two named toolkits are absent. The SPEC row requires "the coding toolkit and one kag-era toolkit"; no toolkit or tool row is seeded or imported, and every test writes its own rows (tool_platform.rs:7-9, ::seed_tool :176). Estate import is T14's row.
  • V1's external actions were wrapped, not migrated. The actions named in the inception analysis remain ActionKind::External (crates/actions/src/integrations/external.rs:209 artifacts.list, :224 billing.summary, :239 coding_jobs.create, :278 retrieval.query, plus workers/providers/graphs.list earlier in the file), and a tool's handler_action must name one. No code removes their direct invocation; the guard proves handlers use the executor, not that a job cannot bypass the broker.
  • credential_alias is dead data. It is stored and selected (crates/store/src/tool.rs:71,123,138,155), but no broker or action code reads it; crates/actions/src/tools.rs:17 says the binding resolves the credential, and it does not. There is no sealed-profile resolution and no consumer of auth_adapter='sealed-profile'. SPEC §11.3 step 4 is unimplemented.
  • No budget or rate limit. tool_budget_exceeded (§11.3 step 2) has zero hits under crates/, and tool_binding.rate_limit_per_min is enforced nowhere.
  • Storage is not job-facing. JobStorage is referenced only by crates/actions/src/storage.rs and tests (tool_platform.rs:518, s3_wire.rs:79); no action or tool calls it. The round-trip test uses the in-memory store when no endpoint is configured (tool_platform.rs:515), and the prompt test compiles copilot_system@1 (:586) rather than a prompt from a job that used storage.
  • Closed-schema and immutability invariants are convention, not constraint. The migration requires input_schema to be an object but not additionalProperties:false; the toolkit comment calls a published version immutable, but no trigger or constraint prevents an UPDATE.
  • The broker's step order diverges from the design. The published design orders the ceiling and the tenant's approvals before input validation (step 3 then step 4); the implementation validates the input first and takes the destructive approval after (crates/actions/src/broker.rs:invoke_broker). Both refuse a bad call, but a validation failure in the implementation is reported before an approval is requested, so a caller can learn a call is invalid without an approver seeing it. Disclosed, not corrected.
