Project brief — T2 Decision ladder (retrospective, 2026-11-21)

Outcome

The conveyor has one decision ladder. An L0 rule, an L1 laya choice and an L3 human decision are written through one decision row shape; each row pins the policy, refinement and laya-config versions it read; a tenant refinement changes a threshold without a build; and a generated draft is applied only through ladder.apply_draft with a human draft.apply decision backed by an approved gate. Six findings remain open, and v1-t2-1 — documents.compose can attach a generated draft with no gate — keeps the project active.

Boundary

T2 owns the ladder row, the policy, refinement and laya-config rows, the human gate and the draft-apply gate. It does not own the PM job (T3), the tool platform (T13), metrics and metering (T11), cadence materialisation or PI planning (T10), the S15 judge's own laya call in crates/actions/src/process/judge.rs, or the ADR board's decisions.* family, which keeps its name. The console does not gain a ladder panel in T2; ladder.list is the read.

The S16 inference_call ledger for the L2 generation split. The action registry, the #[action] declaration and the real-Postgres test harness.

Acceptance

The SPEC_V2 §12 T2 gate: a rule, a laya decision and a human decision produce the same audit shape; a tenant refinement changes a threshold without a code change; every decision pins the refinement and laya-config versions; a generated draft cannot transition a card. The first three are green by decision_ladder.rs; the fourth is green on ladder.apply_draft and documents.update and red on documents.compose (v1-t2-1). The rework's acceptance instrument is acceptance/programme/T2.toml.

Capabilities

One decision audit shape across L0, L1 and L3; version-pinned and reproducible decisions; tenant refinement without a build; the laya config row; the person-only human rung; the gated draft application; the decision.changed event; tenant-scoped rows and indexes.

Plan

Held to docs/SPEC_V2.md §12 (T2) and §7.1–§7.5. The project row's plan pointer is docs/SPEC_V2.md#12 with plan_status: draft; no separate plan document exists. Delivered 2026-11-17 by commit 39363ba8 (#73, #286); reworked retrospectively 2026-11-21 and left active.

Risks

  • documents.compose attaches a generated draft with no gate (v1-t2-1, P0): the fourth clause is not true until the create path checks the draft class.
  • L1 records a caller-supplied answer and never calls laya (v1-t2-2): the ladder's confidence is only as good as its caller.
  • refinements.publish and decision_policies.update are ungated (v1-t2-3): a tenant can weaken a safety gate without an approval.
  • Options and questions are inline request data (v1-t2-4): the option set is not independently versioned and the policy has no fire_when or min_confidence.
  • The §7.5 budget slug has no implementation (v1-t2-5).
  • A human decision does not pin its approval to its gate (v1-t2-6).
