Tranches and dependencies

  • The tranche numbers are the programme's dependency levels; a project sits in the tranche its prerequisites allow (docs/SPEC_V2.md §12; the P0 plan §7).
  • Dependencies are declared as meta.depends_on in the seed and measured as blocked_by in the coverage; the programme gate refuses a run whose blocking dependency is open with 409 blocked_by.
  • The delivery projects T1–T17 sit behind P0 (the definition set) and, for T1, T0's closed contracts.

Resources and budget

Not stated in the seed. The programme's source data carries each project's plan and units, not a resource or budget figure. The honest statement is that the resource assumption is the project's slice plan and the owner's allocation; a per-project budget is a programme decision that has not been taken. The gap is recorded rather than filled with a number.

Delivery risks

  • The definition gate. P0's remaining artefacts are the gate T1–T17's build units wait on; a gap here delays the whole tranche chain.
  • Plan drift. The dossier is generated; a hand-edited plan or an unmeasured status is the failure mode the coverage gate catches.
  • The measured status is a snapshot. A project's built or proposed status is measured at the coverage run; a merged unit not reflected is a coverage defect, not a new status.
  • The open units. 33 projects carry open units at this coverage run; the gap column names each project's gap.
