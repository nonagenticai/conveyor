Entries

Seven capabilities make the skeleton a platform rather than a crate pile. Tenancy isolation and identity are the entry capabilities; job execution and realtime events are the runtime capabilities the gates exercise; audit, entitlement and operability are the trust capabilities that make the rest safe to expose. Each capability names the outcome it enables, so a later slice can ask which capability it consumes instead of which function it calls.

Links

The map derives from the solution concept and from the requirements catalog: every capability is carried by named components and every requirement falls under a capability. The data entity catalog derives from this map, because the rows exist to serve the capabilities. This is the chain the Architecture Board reviews: stakeholder → driver → requirement → component → capability → data.

Document

The document records the capability view as the plan's §3 scope and §5 deliverables imply it. The retrospective states one limit: operability is level 2, not level 1, because S02 ships health and metrics but not the dashboards or alerts that S14 and T11 own. That distinction keeps the map from claiming a monitoring capability the skeleton does not deliver.
