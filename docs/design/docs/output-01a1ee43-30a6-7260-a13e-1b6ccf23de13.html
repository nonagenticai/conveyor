Context and boundary

T16 owns one pipeline: a tenant supplies an SOP, an RDF/OWL/Turtle document or a process diagram; the conveyor stores it as an untrusted source, converts it into draft procedural knowledge (PKO) and a draft PDDL procedure, and publishes both behind a human gate. It owns the PKO aggregate, tenant editing, and capability/job design from an SOP (§5.6–§5.7); not the tool broker (T13 #76, absent), knowledge store, run engine, approval policy (T2, built) or T17.

The executable carrier is process: migration 0035 renamed procedure/procedure_step to process/process_step and freed procedure for the SOP a step is judged against; §10.3 uses the old names, and this design follows the schema. External calls go through tools.call only (§11.3). The tool tables are absent, so live conversion waits; fixture conversion, PKO storage and the PDDL run path do not.

Decisions

D1 — the executable procedure is a process extension, with the source pointer checked at publish. Alternative: a new procedure_draft aggregate, checked only at bind. Consequence: one store and one publish/run path (P1); the plan's old table names need correction.

D2 — PKO is relational, with no triple store or reasoner; edits copy forward. Alternative: an embedded RDF store with in-place edits. Consequence: no SPARQL or inference; conversion must complete at publish, and an unmapped OWL construct is refused.

D3 — namespace split. Intake in procedures.*, PKO in pko.*, executable publication in processes.publish; a second procedures.publish is never created. Alternative: rename the SOP-judge family. Consequence: docs say "SOP" for the judge and "process" for the executable.

D4 — deterministic conversion for structural formats, generation for prose. Alternative: one LLM converter. Consequence: RDF/OWL and BPMN are reproducible; prose needs ledgered model calls and a human gate (P2, P5).

D5 — PDDL subset is STRIPS with typing over ground literals. No quantifiers or numeric fluents. Alternative: full PDDL 2.1. Consequence: some SOPs are refused by name; no planner dependency.

D6 — all backends through the T13 broker. Alternative: direct HTTP. Consequence: live paths wait for #76; T16 fails closed (409 tool_not_ready) rather than calling directly (P8).

Acceptance

Gate, verbatim (§12 T16): "a real SOP, an OWL file and a BPMN diagram are each ingested end to end; the procedure draft is published behind a human gate; a tenant edits a PKO entity and the change is versioned; a job bound to the procedure runs the PDDL steps; an unreviewed source never binds".

  • A1 — SOP end to end. PDF fixture → approved source → draft process with a PDDL step. Verify: crates/actions/tests/t16_ingest.rs (to create at #85).
  • A2 — OWL/Turtle end to end. Draft PKO release publishes after approval. Verify: crates/actions/tests/t16_ingest.rs (to create at #85).
  • A3 — BPMN end to end. Activities become steps, gateways become gates. Verify: crates/actions/tests/t16_bpmn.rs (to create at #85).
  • A4 — human gate. Publish refuses an unapproved process; approvals.decide clears it. Verify: crates/actions/tests/t16_gate.rs (to create at #85).
  • A5 — PKO edit versioned. pko.edit yields version 2; updating published rows is refused. Verify: crates/actions/tests/t16_pko_version.rs (to create at #85).
  • A6 — PDDL steps run. A bound job refuses a false precondition; an effect sets the next. Verify: crates/actions/tests/t16_pddl_run.rs (to create at #85).
  • A7 — unreviewed source never binds. A draft source refuses a binding; approval clears it. Verify: crates/actions/tests/t16_source_bind.rs (to create at #85).

Driver → goal → objective. Driver: SOPs, ontologies and diagrams cannot execute. Goal: one governed pipeline produces reviewed procedural knowledge and an executable procedure. Objective: the five gate outcomes hold.

Solution concept. Source → governed_asset(sop_source) + document → conversion → draft pko_release + draft process → approval → publish → bind → run with PDDL.
