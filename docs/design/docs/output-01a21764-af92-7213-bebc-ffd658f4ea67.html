Metadata

The catalog names the platform's four data families and the store that owns each. It is an inventory with an owner per row, not a schema: the schemas live with the application and the stores live with the platform. A data family without an owner is a finding.

Entries

The operational rows are the record: projects, cards, runs, approvals, programme rows and the rework register, all in Postgres. The document bytes are in MinIO with tenant separation. The images are in the one registry. The secrets are per-service and never cross a service boundary, which is the platform's blast-radius rule.

Links

Each family names its backup or restore path: the nightly dump and its offsite relay for Postgres, the MinIO bucket probe and the restore drill for bytes, the PV snapshots for the registry and the SOPS layout for secrets. The catalog is what the restore drill walks.

Document

The catalog is the platform's data boundary. A new store is a design change; a second database user for another service is forbidden by the programme's invariants. The four families are the whole platform state, and the deliverable's evidence includes the restore path for the first.
