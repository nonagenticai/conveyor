  1. No cadence or benefit execution actions. The action registry at this baseline names only cadences.create|list|update|delete and the existing tranches.* / benefits.* families (crates/actions/src/spine/mod.rs); git grep '"lessons\\.' finds nothing. The design's cadences.plan|demo|retro|refine and benefits.strategy|realization_plan|report do not exist. Execution is the server tick; there is no HTTP/MCP action by which a person or agent plans a PI, runs a demo or retro, or asks for refinement. Refinement in particular has no implementation: no stale-item read exists at this baseline, so D-T10-6 is unbuilt.
  2. wbs_node.planned_cadence_id absent. git grep planned_cadence_id origin/main returns nothing; the design's D-T10-2 and its migration were not delivered. Idempotency is cadence state plus wbs_node.card_id IS NULL, so no row records which cadence planned it, and a later PI period draws again from whatever remains unplanned.
  3. benefits.update(status='realized') is unguarded. crates/actions/src/spine/mod.rs:benefits_update accepts realized in its status list and passes it into BenefitPatch; git grep -i realized over crates/store/src/spine.rs returns nothing, so no store guard exists. Clause 5 is proven on the transition/realization path only. This is the bypass T10's own inception analysis listed as risk 4 and D-T10-9.

The inception analysis said "Do not build lessons (T8)" and D-T10-5 said the retro owns no lesson row, yet 0056 creates lesson and propose_lesson_tx writes it, with the independent-ref rule explicitly left to T8 in the function's own comment.
