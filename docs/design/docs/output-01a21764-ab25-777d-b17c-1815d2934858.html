Metadata

The concept diagram is the estate the platform owns. Five nodes, each with one job: the control plane and primary, the registry and volumes, the compute pool, the only CI node and the storage plus standby. Nothing crosses the site split invisibly: the datacenter pair and the home pair are named in the programme's infrastructure record.

Entries

The diagram's rows are the nodes and their roles. The edges the platform cares about are the CI path from ci-1 to the registry, the registry pull on every node, the Postgres path through pgbouncer for pods and postgres.example.com for hosts, the MinIO path for object bytes and the ingress path from the Cloudflare tunnels to istio.

Links

Every path has an owner and a probe: the runner list for CI, the CA-backed push for the registry, pg_is_in_recovery for the database, the bucket probe for MinIO and the public window probe for ingress. The diagram is the map the requirements catalog's verifications walk.

Document

The diagram is deliberately small: a platform that needs a second CI node or a second registry is a design change with its own decision, not an extra box. The estate's five-node shape is the current answer and the programme's rules keep it singular where singularity is the requirement.
