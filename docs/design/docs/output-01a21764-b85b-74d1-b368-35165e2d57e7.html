The context diagram places the platform between the programme it serves and the external services it uses. The programme is the conveyor buildout; the estate is the five nodes; the externals are GitHub for source and CI, Cloudflare for the public window and the tailnet for private transport; the tenants are nonagentic, AHTAPol and w2v.

Entries

The diagram's rows are relationships, not boxes: the programme is served, GitHub is depended on in both directions, the network is exposed through two paths, and the tenants are served under separate boundaries. The tenant boundary is the platform's licensing and isolation rule, not a deployment detail.

Links

Each relationship has a failure mode the platform owns: a GitHub outage stops merges and preflight; a Cloudflare outage closes the public window; a tailnet fault splits the sites; and a tenant boundary breach is the one failure the platform must never allow. The diagram is the map the platform's incident procedures use.

Document

The context is stable across tranches, which is why it is a platform artefact rather than a project one. A new external service or a new tenant is a context change with a decision, and the diagram is updated with the decision rather than after it.
