Project brief — S02 Skeleton (retrospective, 2026-11-21)

One page: what S02 changed, what it reused, and how it is accepted. Recorded retrospectively on 2026-11-21 under delegation 01a1ff1f-e4ba-72dc-9c1a-13049933cf14; S02 closes on the P2 proof landed in this batch; issue #2 named a test that did not exist and now does (apps/server/tests/jobs_lease_two_workers.rs, d367a4a9).

Outcome

conveyor has a running ten-member Rust workspace and one conveyor binary over Postgres 18, with eleven platform tables under forced row-level security, OIDC and dev login resolved through membership, a fail-closed app_licence gate, a fenced job runner and a replaying SSE stream — so every later slice starts from one tenant-scoped base instead of forking one.

Boundary

Out of S02: domain aggregates and tables (S03); the action registry (S04); board/run/approval endpoints (S03–S06); the Keycloak realm and cluster deploy (S14); the licences service (D12); pgvector/search (S07); the UI (S12); and .github//git (CONTRACT §13).

Surfaces this project must not fork: the tenant is resolved from membership and never a client header (CONTRACT §9); /api routes stay unversioned; apps/web stays a dependency-free placeholder until S12 (S2-D7).

  • strata_rag src/tenant.rs, src/metrics.rs and tests/common/mod.rs — Tenant(Uuid), OnceLock metrics and container cleanup; token scopes were not carried.
  • fr backend/src/lib/licence-introspect.ts, require-fr-license.ts and backend/src/workers/ — the positive-only cache and the 14 setInterval names as job kinds; the Redis cache and the timers were not carried.

Inception units

  • The ten-member workspace and exact pins are the base every later slice extends (plan §5).
  • Eleven platform tables exactly, with nine tenant-owned tables under ENABLE + FORCE RLS and a FOR ALL policy that carries both USING and WITH CHECK (plan §5).
  • TenantId is typed into the store layer, so an unscoped query is a compile error; begin_scoped is the only tenant GUC writer (plan §5 Tenancy; S2-D1).
  • Login resolves a verified subject through membership to exactly one (app_user, tenant); dev auth is a development transport only (plan §5 Auth; S2-D6).
  • The licence gate reads app_licence only and fails closed; core requests never call the licences service (plan §5 Auth).
  • Jobs are claimed with FOR UPDATE SKIP LOCKED and a fenced lease token; a stale token writes nothing (plan §5 Jobs; crates/store/src/jobs.rs).
  • /api/events replays by event.seq inside the subscriber's tenant scope; pg_notify is a doorbell, not a payload channel (plan §5 SSE; S2-D4).

Acceptance

Scenario: two tenants are isolated including RLS. Given tenant A and tenant B each have a row in event, when the runtime role is scoped to A, then count(*) FROM event returns none of B's rows, a forged tenant_id = B insert fails WITH CHECK, the owner also sees 0, and the superuser sees both. Verify: cargo test -p conveyor-server --test rls -- --nocapture

Scenario: login works. Given migrate --dev-seed has created dev-a/alice and dev-b/bob, when Bearer dev:alice calls /api/me, then it returns 200; and with APP_ENV=production the process exits non-zero. Verify: plan §7 row "Login works"; apps/server/tests/rls.rs.

Scenario: a job survives a kill. Given JOB_LEASE_SECS=2 and a worker killed with SIGKILL mid-handler, when a second worker starts, then the row is reclaimed on lease expiry, attempts increments, and the stale token completes nothing. Verify: cargo test -p conveyor-store --test jobs and cargo test -p conveyor-server --test jobs_kill.

Scenario: SSE replay. Given three events and a reconnect with Last-Event-ID of the first, when the stream resumes, then the second and third arrive once each in seq order and tenant B's events are absent. Verify: cargo test -p conveyor-server --test events.

Scenario: audit is append-only and the licence gate fails closed. Given the runtime role, when UPDATE audit_event runs, then permission is denied; given no app_licence row or an unknown status, when a gated request runs, then it returns 403 problem+json. Verify: cargo test -p conveyor-store --test audit_idempotency and cargo test -p conveyor-auth --test licence.

Scenario: a long handler is not reclaimed under two workers (issue #2 P2). Given JOB_LEASE_SECS=2 and a handler held for four leases, when two worker processes poll the same tenant, then the handler runs once (attempts = 1, one stub call), the finish is succeeded, and the lease is cleared and not resurrected. Verify: cargo test -p conveyor-server --test jobs_lease_two_workers

Full gate (plan §7): cargo fmt --check; cargo clippy --workspace --all-targets -- -D warnings; cargo test --workspace; cargo run -p conveyor-server -- --print-openapi | jq -e '.paths["/api/events"]'; cargo run -p conveyor-server -- migrate; docker compose up -d --build && curl -sf localhost:8930/health/ready.

Risks

  • RLS owner bypass: without FORCE the owner reads everything, so an owner-role test passes while production leaks. First check: run the isolation test as conveyor_runtime and print current_user, with a superuser positive control.
  • sqlx::migrate! path: it resolves against the defining crate's manifest directory. First check: the embedded-set test asserts exactly [(1, "platform")].
  • LISTEN versus PgBouncer: LISTEN is session-scoped and PgBouncer is transaction-pooled. First check: the SSE test uses a dedicated direct DATABASE_LISTEN_URL.
  • pg_notify payload limit is 8,000 bytes. First check: the doorbell sends seq::text only.
  • R6 and R8: the plan forbids adding Redis for rate limits or caches and names auth/tenancy the highest bug surface. First check: rate limits and caches are in-process or Postgres advisory locks, and current compose.yaml carries db, pgbouncer and app only; the RLS test's three-role control.
