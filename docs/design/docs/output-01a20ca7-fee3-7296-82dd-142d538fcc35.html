T19 — Architecture design (PSA and HLD)

Context and boundary

T19 adds a decision forum over the existing four units. It does not add a fifth unit, a chat system, a second decision store or a calendar dependency. The architecture covers the meeting aggregate, the participant extension to approval_decision, the minutes governed-asset kind, the meetings.* action family, the Meetings destination and the two consumer seams (governance_body and programme_cadence). The T18 UI lane is a consumer of the destination row and is not rebuilt.

This is a tailored ADM set for a software delivery slice; it is a document set now and imports as typed architecture_artifact rows when the T9 repository is used. Every artefact carries the standard's common metadata: title, status, version, owner, reviewer, review date, purpose, stakeholders, scope, related project and its published document; links use derivation | realization | reuse | dependency.

C3 — Conceptual data diagram

meeting_type (policy) → meeting (instance) → meeting_agenda_item (resolved approval) → meeting_position (participant stance) and approval_decision (one per qualifying seat); meeting_attendance binds participants to seats; governed_asset(minutes) derives from the rows; project_dependency receives commitments; card receives actions.

D1 — Technology view

PostgreSQL 18 with RLS on every new table; the existing Rust action registry and HTTP/MCP surfaces; the Leptos console route /meetings; the existing Telegram channel adapter and MCP task input request; an ICS feed rendered from attendance. No Redis, no new port, no hosted model, no calendar service, no AV service.
