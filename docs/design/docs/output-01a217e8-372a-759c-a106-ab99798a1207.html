Entries

Twelve components and edges describe the skeleton. One binary exposes four subcommands and serves the API; five crates divide the store, auth, API, domain and error surfaces; two apps reserve the web and server edges. Postgres 18 is the record and the only place tenancy is enforced; Redis Streams is a nudge, not a second record; Keycloak and the licences service are consumed, never configured here. The job runner and the SSE stream are the two stateful components the gates exercise, and the audit writer is the append-only edge every decision depends on.

Links

The diagram realizes the requirements catalog: each component names the requirements it carries, and each requirement has at least one component. It derives from the business capability map in the next phase, because the capabilities are what the components exist to provide. The data entity catalog names the rows these components read and write, so the component picture and the data picture cannot tell different stories.

Document

The document records the solution as the plan's §5 deliverables describe it. The retrospective makes one boundary explicit: the worker is a process over the same binary and the same database, not a separate service, so a restart is a process restart and the lease is the only coordination primitive. That is the design the kill and two-worker proofs exercise, and it is why the proofs can run as real child processes against a real Postgres.
