Candidate Solutions — SPEC-V2 (retrospective, 2026-11-26)

Candidates

Four routes were considered. The first keeps V1 and adds ad-hoc agents, which preserves the working machine and leaves the organisation, cadence and meta-jobs absent. The second adopts a field framework — CrewAI, ChatDev/DevAll or n8n — and inherits their conversation model. The third is V2 as specified: the conveyor owns the whole model in four units, with typed rows and gates. The fourth adds an external executor runtime beside the internal one, and D61 defers it until four stated conditions hold.

Criteria

The routes are judged on five criteria the plan already fixes: one record per fact (P1), so no concept is stored twice; no speculative aggregate (P10), so a table exists only because a named procedure uses it and a metric reads it; tenant configuration over code (P11), so policies are versioned rows; self-containment (D33), so the conveyor owns its model and the agent platform is a front end; and measurement before adoption (P5), so a change is adopted because a held-out instrument moved. A sixth, narrower criterion is honesty of claim: no certification or conformance badge (§8.6).

Options rejected

Keeping V1 and adding ad-hoc agents is rejected because the organisation spine, the programme cadence, the meta-jobs and the operations perspective do not exist, and the improvement loop has nothing staffing it. The field frameworks are rejected because they build agent conversations, while organisations run on positions, work products, gates, baselines and evidence; the measured n8n estate — 348 workflows, 280 of them the generated card-type by list matrix, each with its own error exits — is the plan's own caution (§1.3, §1.4). The external runtime is deferred, not rejected: D61 names the four conditions, and the seam in T0 preserves the option at near-zero cost.
