Project brief — T13 tool platform (retrospective, 2026-11-26)

Outcome

T13 made one governed call path real: every conveyor-internal run reaches a job backend through tools.call under a binding row's authority, with the effect class, the tool budget and the closed input schema decided before any network call, and exactly one tool_call row and one tool.called event recorded per dispatched call. The six SPEC_V2 §12 clauses are proved by named wire-level tests in crates/actions/tests/tool_platform.rs, 17 of 17 passed at lane head 582e2dc6 on 2026-11-22 against a fresh Postgres 18 and a counting HTTP stub.

Boundary

Out of scope: the catalogue actions and the estate import, which T14 owns; the agent platform gateway nonagenticai_mcp_server, which serves the agent platform's own backends and stays outside the conveyor's path (D44, D59); the BYO publication surface (v1-w4a-6); live MinIO wiring (v1-p1110-1); and a production tool_binding writer (v1-p111-1). The slice must not fork T2's run or durable queue, must not become a second catalogue or runner, and must not carry a credential or an S3 key into a prompt or a ledger row.

Reuse sources

  • conveyor_store::secret::create_secret_tx — sealed credentials, reused rather than rebuilt (§11.8).
  • governed_asset kind='tool_draft' — the publication lifecycle of validation, security review, tools.publish and binding (§11.6).
  • event and audit_event — the tool.called event and the audit trail (§11.3 step 7).
  • T2's run and durable queue — tool_binding.run_id targets a run, and §12 places T13 after T2.
  • The predecessor MCP server's coding toolkit as a reference shape only: eleven operations and the mcp_tool_call_audit model, never routed through (D44, D59).

Inception units

The analysis T13 starts from is SPEC_V2 §11.1–§11.10 and the T13 row in SPEC_V2 §12, and its recorded entry point is issue #76, with the follow-on issues #556 (bound toolkits reach the agent executor), #557 (binding and catalogue actions and the full published tool contract) and #630 (the run inspector's executor kind, binding pin and tools panel), all closed on GitHub. The retrospective reconstitutes the governance record over the completed slice — charter, Statement of Architecture Work, the seven A–D artefacts approved by the board, the delivery contract, the WBS deliverable, the Phase-G review, the project brief, the evidence and the closure review.

In the other direction, T6, T7, T14, T15, T16 and T17 depend on T13, with T14's estate import as the first consumer, and a job's calls additionally depend on a destination alias registered and reviewed at publication. Acceptance

The SPEC_V2 §12 gate, executed through acceptance/programme/T13.toml and six named tests: a_bound_job_calls_coding_through_the_broker; one_call_is_one_ledger_row; a_destructive_call_without_approvals_is_refused; a_closed_schema_refuses_before_the_call; a_job_round_trips_a_tenant_prefixed_object; the_compiled_prompt_carries_no_s3_key. Each refusal is asserted on the wire through a counting HTTP stub, so a refusal that reached upstream would fail. The recorded run is 17 of 17 passed at lane head 582e2dc6 on 2026-11-22 against a fresh Postgres 18.

Capabilities

The platform exercises an immutable tool and toolkit lifecycle; binding-scoped access that narrows but never widens; broker dispatch as the single path to a backend; effect-class gating for read, write, destructive and spend; closed-schema input enforcement before egress; a call ledger that makes each call and its cost visible; tenant-separated object storage under an adapter-built tenant prefix with a content hash; and the probe and retirement rules that T14's estate toolkits exercise.

Plan

The plan is one WBS deliverable, 'The tool platform — one governed call path, the call ledger, the schema and effect gates, and tenant-prefixed storage', accepted with WSJF inputs 8, 5, 8 and 5 and evidenced by acceptance/programme/T13.toml and the proving suite. It sits in tranche 3, whose review 01a216d0-d634-738e-985a-00a85cfd48d9 records continue.
