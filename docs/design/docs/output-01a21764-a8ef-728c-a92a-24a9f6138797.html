Metadata

The requirements are the platform's standing obligations, each with a verification a reader can run against the live estate. They are not a wish list: R1–R6 are the paths every delivery project uses, so a broken one blocks a tranche rather than one project.

Entries

R1 is the CI node's taint and runner pool; R2 is the registry's address and the CA a hand push needs; R3 is the primary and the single standby; R4 is the bare-metal MinIO unit; R5 is the ingress path behind the Cloudflare tunnels; R6 is the one-service-one-credential rule. Each row names the verification that proves it, not the configuration that assumes it.

Links

The catalog is the reference for the platform's test and acceptance records. A requirement that cannot name a verification is not a requirement; it is removed or rewritten rather than carried as prose. The six rows are the set the platform's deliverable and the tranche reviews hold it to.

Document

The platform's record carries the requirements as rows; its published brief cites them and its phase-G review judges against them. The catalog does not duplicate the estate's own runbooks: it states what the platform must be able to do and leaves the how to the operating procedures.
