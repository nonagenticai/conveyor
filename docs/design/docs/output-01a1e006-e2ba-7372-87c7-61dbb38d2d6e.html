Business case

Programme: conveyor buildout · Status: adopted by P0 · Date: 2026-11-15

Why now

  1. The machine works; the organisation does not exist yet. V1 is live at conveyor.nonagentic.ai: projects, boards, cards, runs, approvals, documents, procedures, capabilities, knowledge, memory, an inference ledger, evals, a benchmark harness and the compiled-prompt pipeline (docs/SPEC_V2.md §1.1). What it lacks is the organisation that staffs and governs the work — no industry, department, job, programme cadence, PM, coach, kata, development or operations position (docs/SPEC_V2.md §1.1). V2 is the difference between a work system and an operating organisation.
  2. The estate has services that must be governed, not just kept running. docs/plans/04-TOOL-ESTATE-INVENTORY.md records the absorption state: scientific and lean4 are absorbed but not deployed; research and media are in flight; the coding fleet is still the Python deployment; the eighteen w2v stage directories are a deliverable vocabulary, not services. A tool platform with a probe, a version and a ledger is cheaper than an unowned fleet.
  3. The public repository changes the economics of review. The code and this programme's definition set are public; a contributor can read the design, open an issue and propose a change without an account. The cost of an outside review drops to a GitHub session.
  4. The development loop is the bottleneck. The measured audit in docs/plans/development-process-speed.md records a 102-minute run with 75 minutes before the heavy job starts, 27 minutes of job time and 18.9 minutes of tests. Improving that loop pays back on every one of the 48 projects.

Cost and risk posture

  • Engineering cost is concentrated in T0–T3 and T13 — the organisation and tool spines. Every other slice is a job that uses them (docs/SPEC_V2.md §12). The programme does not need all 48 projects before it produces value; P0's definition set is the gate that prevents building the wrong 47.
  • The public repo is the exposure. No secrets, tokens, private hosts or customer data enter the repository or a published output; the public pack applies the snapshot's redaction and scripts/ci/no-private-refs.sh is the gate. Public input is GitHub only; there are no in-app public accounts.
  • CI is the recurring cost. GitHub-hosted runners are free for public repositories; the measured risk is queueing and supersession, not spend. The repo's CI budget is two runs per unit: the PR and its merge (docs/plans/03-DELIVERY.md); the local gate runs first.
  • The migration risk is drift. V1 stays live until S14's cutover; V2 does not re-open V1 slices. A V2 aggregate that no tenant uses does not ship (P10), and a retired binding refuses rather than silently serving a stale release.

Licensing and boundary

The licensing frame is per-tenant, opt-in and public-first: the repository and the programme site are public; a tenant's use of a V2 aggregate is a tenant decision, not a programme default. There is no per-app delegation header and no hidden dependency on the agent, fr or care-bus applications at runtime (docs/SPEC_V2.md §1.2, D33). The agent platform remains a user-interaction front end over MCP.

Decision

Approve P0's definition set and adopt the programme plan. The benefit is not a document: it is the operating loop in T12, measured by decision rows, tool calls, run evidence and the maturity levels in T11. The cost is the T0–T3 + T13 spine and the discipline of the public gates.
