GEMBA-WALK — Project brief

Amendment 2026-11-27 (CR-WALK-001, ADR 0024). The client is served at https://game.nonagentic.ai/ at the root, with its own public client conveyor-game in the conveyor realm; the operator origin's /walk/* 308s to it, and /walk/ remains only the no-host dev/CI shape. The action count is 598 (572 attributes + 26 manual registrations). Read "/walk/X" in the analysis sections below as the app path /X on the game host.

Outcome

A signed-in tenant member can complete every operator task in a separate, game-style client at https://game.nonagentic.ai/ — the same reads, writes, gates and refusals as apps/web — and the parity is measured by an instrument, so the owner can decide whether the walk becomes the primary UI on evidence rather than on a mock.

Boundary

In: a static client at https://game.nonagentic.ai/ (same image and service, a second host; the operator origin's /walk/* redirects to it); route parity with the 52 apps/web route patterns at the host root; reachability and schema-rendering of the 598 registered actions; the seven wings and their rooms; seats as view presets; DOM sheets as the only work surface; the WorldView port and the canvas-2D baseline; the parity instrument and its frozen census; Playwright specs per destination; the host dispatch, the /walk 308 and the game-host boundary; its own public Keycloak client conveyor-game and the live sign-in proof; accessibility and performance budgets; deployment; the P6 primacy runbook.

Out: no table, action, event, port or decision store; no second backend or read model; no SSR; no native mobile, chat, audio or video; no calendar/AV dependency; no fixture or embedded snapshot; the mock is not committed and never the client's source; the design pack at /design/ is unchanged; apps/web is not retired before the P6 gate; primacy is not claimed from prose.

It must not fork: the action registry, the decision store, the read models, the auth flow's identity provider, or the Playwright contract. A capability the server does not expose is an honest gate, exactly as in apps/web.

Acceptance

Each part carries a BDD scenario with its Verify: command; the plan's stage gates are the build's acceptance.

  • Foundation (P1). Given the merged seed and the dev server, when a signed-in member opens https://game.nonagentic.ai/, then the entrance renders the Portfolio reads and one real write round-trips. Verify: npx playwright test -c apps/walk/playwright.config.ts --grep foundation (to create).
  • Read parity (P2). Given every §10.5 destination, when it loads, then loading, empty, partial, error and denied states render with the honest gate. Verify: npx playwright test -c apps/walk/playwright.config.ts --grep reads (to create).
  • Write parity (P3). Given a write action, when it is submitted, then the envelope, If-Match, Idempotency-Key and approval are sent, and a refusal is shown verbatim with no optimistic mutation. Verify: the contract test per action family (to create).
  • Retained V1 (P4). Given the frozen census, when the instrument runs, then every route has a walk route and a spec, and every action is reachable and schema-rendered. Verify: python3 scripts/build-walk-coverage.py --check (to create at P0).
  • P6 gate. Given the instrument green, when the accessibility, performance and primacy checks run, then the owner signs the primacy decision — or the walk stays an alternative client. Verify: the P6 runbook (to create).

Capabilities

The owner/sponsoring group (primacy decision), the programme manager (tranche and issue queue), the programme architect (ADM and contract), the delivery seats (Product owner, Programme, Owner, Reviewer presets), platform/security (serving, identity, headers), and accessibility/UX (keyboard and contrast). The customer is not a seat: the external stakeholder reads the public pack (D48).
