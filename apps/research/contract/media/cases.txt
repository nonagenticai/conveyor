# Golden cases for media-discovery, one per line:
#
#   name|METHOD|path|body
#
# The reference is booted by ../run-local.sh with every network adapter disabled and no licence
# token, against a scratch database holding `seed.sql` — so every happy-path answer below comes
# from the reference's own code and its own rows, and every miss answers from its own 404 branch.
#
# Two substitutions are made by capture-goldens.sh as it walks this file in order:
#   {ITEM_ID}       — the id of the first row in seed.sql
#   {COLLECTION_ID} — the id in the body of `collection_create`, captured earlier in this file
#
# Order is load-bearing. The collection cases run create → add → get → remove → delete on ONE
# collection, so each answer is captured against the state the previous case left.
#
# Volatile fields (ids, timestamps, request_id, search_time_ms, quality freshness) are declared in
# §"Tolerance" of ../README.md and normalised by the parity test, never asserted away silently.

# that has never been scored (it computes in memory and writes nothing).

# An empty name is accepted, and collection_type defaults to playlist
collection_create_validation|POST|/api/collections|{"name":""}
collection_add_items_ok|POST|/api/collections/{COLLECTION_ID}/items|{"item_ids":["10000000-0000-7000-8000-000000000001"]}

collection_add_items|POST|/api/collections/{COLLECTION_ID}/items|{"item_ids":["00000000-0000-7000-8000-000000000000"]}
